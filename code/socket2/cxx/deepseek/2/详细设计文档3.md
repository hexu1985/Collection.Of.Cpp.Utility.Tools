# unpsock C++ Socket 库详细设计文档

## 1. 概述

### 1.1 项目定位

`unpsock` 是一个面向 Linux（POSIX 接口）的现代 C++ Socket 库。与 Asio、POCO 等跨平台异步库不同，`unpsock` 刻意放弃跨平台抽象与复杂异步模型，聚焦于 **SoC / 嵌入式 Linux 平台** 的易用性与性能：

| 维度 | unpsock 的选择 | 与 Asio/POCO 的区别 |
|------|----------------|---------------------|
| 平台 | 仅 POSIX / Linux | 不做 Windows / IOCP 抽象 |
| 并发模型 | 同步阻塞 + 可选 non-blocking + Selector | 无 Proactor/Reactor 框架、无协程、无回调链 |
| 类层次 | 扁平（Address / Socket / Selector 三实体） | 无模板策略、无 policy-based 设计 |
| 内存管理 | `std::string` / `std::vector` 自动 RAII | 调用方无需管理 buffer 生命周期 |
| 错误处理 | **双风格**：`std::error_code` 与异常 | 与 Asio 类似的 `error_code` 版 + 自定义异常版并存 |
| 接口风格 | 参考 Python `socket` 模块 | 直白、命令式，学习成本低 |

### 1.2 设计目标与原则

| 原则 | 说明 |
|------|------|
| **零隐藏成本** | 所有封装在非热点路径上；保留裸 fd、原始 `sockaddr` 指针等接口，允许调用方绕过封装直接使用 POSIX 接口 |
| **双错误风格** | 每个可能失败的接口同时提供 **异常版**（无 `ec` 参数，失败抛 `SocketError` / `AddressError` / `SelectorError`）和 **错误码版**（带 `std::error_code&` 出参，`noexcept`）。原型验证用前者，生产复杂逻辑用后者 |
| **POD 化的 kernel 参数** | `getsockopt` / `setsockopt` 采用模板 + `socklen_t` 长度校验，避免 `int` / `timeval` / `linger` 等类型错配 |
| **不做过度抽象** | `Selector` 只有四个虚函数（注册、修改、移除、等待），不做 "handler 注册"、不做 "事件循环" |
| **RAII 完备** | `Socket` 移动语义、析构自动关闭；`Address` 值语义；`Selector` 析构释放后端资源 |
| **header-only 交付** | 全部实现以 `inline` / 模板形式交付，零编译依赖，便于集成到嵌入式工程 |

### 1.3 逻辑模块组成

库在逻辑上由三个实体类和三个支撑设施构成，与文件组织无关：

```
┌─────────────────────────────────────────────────────┐
│                    unpsock（逻辑模型）                │
│                                                     │
│   Address         ── 地址值对象（值语义）             │
│   Socket          ── 句柄 RAII（移动语义）            │
│   Selector        ── I/O 多路复用抽象（多态）         │
│                                                     │
│   ├─ select 后端  ── Selector 的具体实现              │
│   ├─ poll 后端    ── Selector 的具体实现              │
│   └─ epoll 后端   ── Selector 的具体实现              │
│                                                     │
│   支撑设施：                                         │
│   ├─ 异常体系     ── SocketException 及派生           │
│   ├─ 错误类别     ── gai_category / selector_category│
│   └─ 主机名查询   ── local_hostname()                │
└─────────────────────────────────────────────────────┘
```

逻辑依赖关系（自底向上）：

```
错误类别 / 异常体系
        ↑
    Address ──→ Socket ──→ Selector ──┬─→ select 后端
        ↑                            ├─→ poll 后端
  主机名查询                          └─→ epoll 后端
```

上述模块在交付形态上以头文件集合提供，但本设计文档仅关注**逻辑边界与契约**，不规定物理文件划分与包含顺序。

### 1.4 命名空间与命名风格

- 全部符号位于 `namespace unpsock`，内部辅助位于 `unpsock::detail`。
- 类型使用 `PascalCase`（`Address`、`Socket`、`EpollSelector`），函数/方法使用 `snake_case`（`from_ip`、`sendall`），成员变量后缀下划线（`fd_`、`storage_`）。

## 2. 错误处理设计

### 2.1 异常层次

```
std::system_error
  └── unpsock::SocketException          // 通用基类；持 std::error_code + what
        ├── unpsock::AddressError       // 地址解析 / DNS（默认 gai_category）
        ├── unpsock::SocketError        // 底层 socket syscall 失败
        └── unpsock::SelectorError      // Selector 注册 / wait 失败
```

关键点：

- `SocketException` 继承 `std::system_error`，构造函数同时接受 `int errnum` 和 `std::error_code`。
- `AddressError` 默认用 `gai_category()`，因为 `getaddrinfo` 的返回值属于 `EAI_*` 命名空间，不能映射到 `errno`。
- `SelectorError` 同时覆盖两种来源：`system_category`（后端初始化失败）与 `selector_category`（`AlreadyRegistered` 等）。

`SocketException` 契约：

```cpp
class SocketException : public std::system_error {
    SocketException(int errnum, const std::string& what);
    SocketException(std::error_code ec, const std::string& what);
    int errnum() const noexcept;      // 错误码数值
    std::string errmsg() const;       // 错误描述
};
```

继承 `std::system_error` 以复用 `what()` 与 `code()`，同时提供 `errnum()` / `errmsg()` 便捷访问。

### 2.2 自定义 error_category

**GaiCategory**：承载 `getaddrinfo` 返回值。

```cpp
class GaiCategory : public std::error_category {
    const char* name() const noexcept override;         // "getaddrinfo"
    std::string message(int ev) const override;         // 委托 ::gai_strerror
};
inline const std::error_category& gai_category() noexcept;   // 单例
inline std::error_code make_gai_error_code(int ev) noexcept;
```

**SelectorErrorCategory**：承载 Selector 内部错误。

```cpp
enum class SelectorErrc {
    Success = 0,
    AlreadyRegistered,   // add 时 fd 已注册
    NotRegistered,       // modify/remove 时 fd 未注册
    BackendUnavailable,  // make_selector 找不到可用后端
    WaitFailed,          // wait 底层失败（errno 用 system_category）
};
```

`SelectorErrorCategory` 实现 `name()` / `message()`（返回英文短语，便于日志检索），`make_selector_ec` 构造 `error_code`。

### 2.3 双风格约定（契约）

所有公有 API 遵循以下模式：

```cpp
// 异常版：无 error_code 出参，失败 throw
void op(Args...);
// 错误码版：error_code& 出参，noexcept，失败置 ec
void op(Args..., std::error_code& ec) noexcept;
```

约定细则：

1. 错误码版**总是先 `ec.clear()`**，成功时 `ec` 为空。
2. 异常版内部调用错误码版，再 `if (ec) throw`——这保证两条路径行为一致。
3. 错误码版标记 `noexcept`（除极少数底层调用如 `std::vector` 分配可能抛 `bad_alloc` 外，逻辑上不抛）。
4. 返回类型为「值」的错误码版，失败时返回**默认构造值**（如 `Address{}`、空 `vector`、0）。

### 2.4 错误类别划分

| 错误源 | `error_category` | 构造方式 |
|--------|------------------|----------|
| 系统调用 errno | `std::system_category()` | `std::error_code(errno, std::system_category())` |
| `std::errc` 通用语义 | `std::generic_category()` | `std::make_error_code(std::errc::xxx)` |
| `getaddrinfo` 返回值 | 自定义 `gai_category` | `make_gai_error_code(rc)` |
| Selector 内部错误 | 自定义 `selector_category` | `make_selector_ec(SelectorErrc::xxx)` |

### 2.5 关键错误路径表

| 场景 | 返回 | ec |
|------|------|-----|
| `recv` 对端正常关闭 | `0` 字节 / 空 vector | 空 |
| `recv` 出错 | `0` / 空 | `system_category(errno)` |
| `accept` 出错 | `{Socket(), Address()}` | `system_category(errno)` |
| `resolve_all` 失败 | 空 vector | `gai_category(EAI_*)` |
| `Selector::add` fd 已注册 | — | `SelectorErrc::AlreadyRegistered` |
| `connect_timed` 超时 | — | `errc::timed_out` |
| `getsockopt<T>` 长度不符 | `T{}` | `errc::invalid_argument` |
| fd 已关闭（`fd_ < 0`） | — | `errc::bad_file_descriptor` |

### 2.6 构造函数重载语义（AddressError）

`AddressError` 同时支持两种构造：

- `AddressError(what, gai_errnum)`：`gai_errnum` 默认 0，适用于 errno/ec 场景。
- `AddressError(ec, what)`：直接携带任意 `error_code`（含 `gai_category`）。

## 3. 地址模块设计（Address）

### 3.1 设计职责

`Address` 是 `struct sockaddr_storage` 的 RAII 值对象，承担：

- 统一承载 IPv4、IPv6、Unix Domain 三类地址；
- 提供强类型构造（`from_ip` / `from_unix` / `from_sockaddr`）；
- 提供 DNS 解析（`resolve` / `resolve_all`）；
- 提供常用地址快捷构造（`any` / `loopback`）；
- 提供字符串化（`ip` / `to_string`）；
- 提供与底层 API 互操作（`sockaddr_ptr` / `sockaddr_len` / `to_storage`）。

### 3.2 数据布局

```cpp
class Address {
    struct sockaddr_storage storage_;   // 128 字节，覆盖所有 sockaddr_*
    socklen_t               len_;       // 实际长度
    Family                  family_;    // 冗余家族标记，快速判断
};
```

统一存储的动机：Linux 上 `sockaddr_storage` 足以容纳 `sockaddr_in`（16B）、`sockaddr_in6`（28B）、`sockaddr_un`（110B）。使用 `sockaddr_storage` 作为唯一载体，避免 `union` + tag 的手工管理。

`family_` 与 `storage_.ss_family` 冗余但保持一致，避免每次重新解释 `storage_` 的头字段；同时作为 `empty()` 判定依据。

### 3.3 枚举定义

```cpp
enum class Family { INET, INET6, UNIX, UNSPEC };
enum class AddrType { STREAM, DGRAM };
```

`detail::to_af` / `from_af` / `to_socktype` 完成与系统常量（`AF_INET` 等）的双向映射，默认 `UNSPEC` 用于「未指定/自动判定」。

### 3.4 支持地址类型

| 家族 | 类型 | 构造入口 | 长度 |
|------|------|----------|------|
| `AF_INET` | TCP / UDP | `from_ip`, `resolve`, `any`, `loopback` | `sizeof(sockaddr_in)` |
| `AF_INET6` | TCP / UDP | 同上 | `sizeof(sockaddr_in6)` |
| `AF_UNIX` | 流 / 数据报 | `from_unix` | `SUN_LEN()`（含 `\0` 截断） |
| `AF_UNSPEC` | 空 | 默认构造 | 0 |

### 3.5 构造 API 矩阵

| 静态函数 | 异常版 | 错误码版 | 说明 |
|----------|--------|----------|------|
| `from_ip(ip, port, family=UNSPEC)` | ✓ | ✓ | `inet_pton` 双栈自适应：先试 IPv4，失败再试 IPv6（`family==UNSPEC`） |
| `from_unix(path)` | ✓ | ✓ | 路径长度 ≤ 107 字节，超长返回 `filename_too_long` |
| `from_sockaddr(sa, len)` | ✓ | ✓ | 由 syscall 返回的 sockaddr 直接封装，`len` 超出 `storage_` 容量视为非法 |
| `resolve_all(host, port/serv, family, type)` | ✓ | ✓ | `getaddrinfo`，返回全部候选 |
| `resolve(host, port/serv, family, type)` | ✓ | ✓ | 取 `resolve_all().front()`，空集 → `EAI_NONAME` |
| `any(port, family)` | ✓ | ✓ | `INADDR_ANY` / `in6addr_any`；`UNIX`/`UNSPEC` 返回 `invalid_argument` |
| `loopback(port, family)` | ✓ | ✓ | `INADDR_LOOPBACK` / `in6addr_loopback` |

### 3.6 DNS 解析实现

基于 `getaddrinfo`：

```cpp
struct addrinfo hints{};
hints.ai_family = detail::to_af(family);
hints.ai_socktype = detail::to_socktype(type);
hints.ai_flags = AI_CANONNAME;
```

`host` / `serv` 为空时对应传 `nullptr`，符合 `getaddrinfo` 语义（可获取本机通配地址/服务名解析）。

结果通过 RAII 守卫（局部对象析构中 `freeaddrinfo`）保证释放；对每个 `ai_addr` 调用内部 sockaddr 转换，转换失败（如地址族未知）时静默跳过，不影响其余结果。

`resolve` 实现为取 `resolve_all().front()`；为空时报 `EAI_NONAME`。

### 3.7 字符串化

| 方法 | IPv4 | IPv6 | Unix |
|------|------|------|------|
| `ip()` | `inet_ntop` | `inet_ntop` | `sun_path` |
| `to_string()` | `1.2.3.4:80` | `[::1]:80` | `/tmp/x.sock` |

IPv6 用 `[...]` 包裹，符合 RFC 3986 host 语法。未知族返回空串。

### 3.8 比较与相等性

`operator==` 按族分别比较：

- IPv4：`sin_port` + `sin_addr.s_addr`
- IPv6：`sin6_port` + `sin6_addr`（`memcmp`）
- Unix：`memcmp` 整个 `sun_path` 定长数组（即使路径较短也按整段比较，语义上等价于「路径完全相同」）
- 其他：视为相等（`UNSPEC` 与其他 `UNSPEC` 相等）

`operator!=` 为 `!operator==`。

### 3.9 `to_in_addr` / `to_in6_addr`

仅当族匹配时输出并返回 `true`，否则返回 `false` 且**不修改**出参。此设计供上层组播等仅支持 IPv4 的接口安全调用。

### 3.10 底层访问

```cpp
const struct sockaddr* sockaddr_ptr() const;
struct sockaddr*       sockaddr_ptr();
socklen_t              sockaddr_len() const;
struct sockaddr_storage to_storage() const;
```

### 3.11 Unix 路径长度计算

`<sys/un.h>` 不保证提供 `SUN_LEN`，设计上要求以「结构体总长 - `sun_path` 数组长度 + 路径长度」的方式计算有效长度，保证 `bind` / `connect` 时长度精确，避免路径后缀垃圾字节。构造 Unix 地址时需对 `sun_path` 做显式 `\0` 截断保护。

## 4. Socket 模块设计（Socket）

### 4.1 类定义与生命周期

```cpp
class Socket {
    int fd_ = -1;
    Family family_ = Family::UNSPEC;
    AddrType type_ = AddrType::STREAM;
};
```

```cpp
Socket() noexcept;                              // 空 socket（fd_ = -1）
Socket(Family, AddrType);                       // 异常版：创建即成功或抛
Socket(Family, AddrType, std::error_code&) noexcept; // 错误码版
Socket(int fd, Family, AddrType) noexcept;      // 接管 fd（供 accept 内部用）

Socket(const Socket&) = delete;                 // 禁止拷贝
Socket(Socket&&) noexcept;                      // 移动：源 fd 置 -1
Socket& operator=(Socket&&) noexcept;
~Socket();                                      // close() if fd_ >= 0
```

**Rule of Five 策略：**

| 操作 | 行为 |
|------|------|
| 默认构造 | `fd_ = -1`，无效句柄 |
| `Socket(Family, AddrType)` | 创建底层 fd，失败抛 `SocketError` |
| `Socket(int fd, Family, AddrType)` | 内部使用（`accept` 产生），直接接管 fd |
| 拷贝构造/赋值 | **删除**，防止双重关闭 |
| 移动构造/赋值 | 接管 fd，源置 `-1` / `UNSPEC`；移动赋值先 `close()` 自身 |
| 析构 | `close()`，幂等 |

`valid()` / `operator bool()` 判断 `fd_ >= 0`。

### 4.2 服务端 API

| 方法 | 异常版 | 错误码版 | 备注 |
|------|--------|----------|------|
| `bind(Address)` | ✓ | ✓ | 直接绑定；异常版 `what` 中拼接地址串 |
| `listen(backlog=5)` | ✓ | ✓ | backlog 默认 5，与 Python 一致 |
| `accept()` → `pair<Socket, Address>` | ✓ | ✓ | `EINTR` 重试；返回 peer 地址 |

**accept 流程：**

1. 循环调用 accept 系统调用，`EINTR` 时重试；
2. 失败 → `ec` 置位，返回 `{Socket{}, Address{}}`；
3. 成功 → 从 `sockaddr_storage` 构造 `Address`，返回 `{Socket(conn_fd, peer.family(), type_), peer}`。

返回值的 `Socket` 通过内部构造函数接管 fd，`type_` 沿用监听 socket 的类型（TCP/UDP）。

**设计说明**：`accept` 保留阻塞语义，非阻塞场景由调用者配合 `Selector` 使用——先 `Selector::add(listen_fd, Read)`，等可读后再 `accept`。

### 4.3 客户端 API

| 方法 | 说明 |
|------|------|
| `connect(Address)` | 阻塞 connect，`EINTR` 重试；失败置 `ec` |
| `connect(host, port)` | 内部 `Address::resolve(host, port, family_, type_, ec)` 再 connect；`ec` 可能来自 `gai_category` 或 `system_category` |
| `connect_timed(addr, timeout)` | **非阻塞 connect + select 超时** |
| `connect_timed(host, port, timeout)` | 同上，带 DNS 解析 |

#### 4.3.1 connect 语义说明

`connect` 可能返回 `EINPROGRESS`（非阻塞），本函数不特殊处理，原样透出，调用者需结合非阻塞语义判断。

#### 4.3.2 connect_timed 实现

非阻塞 connect + `select` 等待可写，是库中唯一独立实现的超时连接逻辑。

**实现步骤：**

1. **保存并设置非阻塞**：取原 fd 标志，置 `O_NONBLOCK`。
2. **恢复守卫**：局部守卫对象在析构时恢复旧标志，保证任何返回路径（含异常）都不残留非阻塞状态。
3. **发起非阻塞 connect**：
   - 返回 0 → 立即成功（localhost 常见）；
   - `errno != EINPROGRESS` → 失败透出；
   - `EINPROGRESS` → 继续。
4. **select 等待**：读写集合同时监听（连接失败时 fd 可读），`EINTR` 重试。
   - `n < 0` → errno 透出；
   - `n == 0` → `std::errc::timed_out`。
5. **SO_ERROR 取真实结果**：读取 `SOL_SOCKET` 的 `SO_ERROR`，非 0 则作为错误透出。

**注意点**：`struct timeval` 在 `select` 返回后可能被内核修改，故每次调用前必须重新构造。恢复守卫在成功路径与失败路径均执行，保证语义一致。

### 4.4 数据收发

| 方法 | 语义 |
|------|------|
| `recv(size_t)` → `vector<uint8_t>` | 分配临时 buffer，接收后 resize 到实际字节数 |
| `recv(void*, size_t)` → `size_t` | 零拷贝；返回字节数 |
| `sendall(data)` | **循环 send 直到全部发出**，抑制 SIGPIPE |
| `send(data)` | 单次 send，返回实际发送字节数（可能短写） |
| `recvfrom(bufsize)` → `pair<vector, Address>` | UDP |
| `sendto(data, Address)` | UDP |

**统一语义（recv 两重载）：**

- `n == 0`：对端关闭，`ec` 为空，返回 0（或空 vector）；
- `n > 0`：正常；
- `n < 0`：`ec` 非空，返回 0（或空 vector）。

接收路径内部处理 `EINTR` 重试。

**`sendall` 循环逻辑：**

```cpp
size_t sent = 0;
while (sent < len) {
    ssize_t n = send(剩余数据);
    if (n < 0) {
        if (errno == EINTR) continue;
        ec = std::error_code(errno, std::system_category());
        return sent;   // 部分发送，调用方需检查 ec 与返回值
    }
    sent += n;
}
```

返回「已发送字节数」而非 bool，是为了在部分发送失败时调用者能准确知道进度（尤其 `sendall` 失败时）。发送路径必须抑制 SIGPIPE（对端关闭时进程不应被信号杀死）。

#### 4.4.1 recvfrom / sendto（UDP）

- `recvfrom` 返回（数据，对端地址）二元组，对端地址由 `sockaddr_storage` 转换；
- `sendto` 使用 `Address` 的 `sockaddr_ptr()` / `sockaddr_len()`，`EINTR` 重试。

### 4.5 查询 API

```cpp
Address getsockname(std::error_code& ec) const noexcept;
Address getpeername(std::error_code& ec) const noexcept;
```

`const` 成员，因为不修改 socket 状态。失败返回 `Address{}`。

### 4.6 非阻塞开关

`set_nonblocking(bool)` / `is_nonblocking()` 通过 fd 标志的读取/设置操作 `O_NONBLOCK` 位。`is_nonblocking()` 在 `ec` 非空时返回 `false`，异常版抛 `SocketError`。

### 4.7 Socket Option 模板接口

```cpp
template <typename T>
T getsockopt(int level, int optname, std::error_code& ec) const noexcept {
    ec.clear();
    T v{};
    socklen_t len = static_cast<socklen_t>(sizeof(T));
    getsockopt_impl(level, optname, &v, &len, ec);
    if (ec) return T{};
    if (len != sizeof(T)) {                    // 长度不符 → 类型选错了
        ec = std::make_error_code(std::errc::invalid_argument);
        return T{};
    }
    return v;
}

template <typename T>
void setsockopt(int level, int optname, const T& value, std::error_code& ec) noexcept;
```

- `T` 必须为 POD（`int`、`struct linger`、`struct timeval`、`unsigned char`、`struct in_addr`、`struct ip_mreq` 等）；
- `getsockopt<T>` 通过 `len` 出参校验：若内核返回的长度不等于 `sizeof(T)`，视为 `invalid_argument`，防止结构体版本不匹配导致的脏读；
- `setsockopt` 直接传 `&value` 与 `sizeof(T)`。

### 4.8 Socket Option 便捷函数

每个 option 提供三件套（除纯写入 option）：

| Option | 读取 | 设置 |
|--------|------|------|
| `SO_REUSEADDR` | `reuse_addr()` / `reuse_addr(ec)` | `set_reuse_addr(bool)` / `set_reuse_addr(bool, ec)` |
| `SO_REUSEPORT` | 同上 | 同上 |
| `SO_KEEPALIVE` | 同上 | 同上 |
| `TCP_NODELAY` | 同上 | 同上 |
| `SO_BROADCAST` | 同上 | 同上 |
| `SO_RCVBUF` | `recv_buffer_size()` → int | `set_recv_buffer_size(int)`（非负校验） |
| `SO_SNDBUF` | `send_buffer_size()` | `set_send_buffer_size(int)`（非负校验） |
| `SO_LINGER` | `linger_opt()` → `struct linger` | `set_linger(bool on, int sec)`（非负校验） |
| `SO_RCVTIMEO` | `recv_timeout()` → `milliseconds` | `set_recv_timeout(ms)`（非负校验） |
| `SO_SNDTIMEO` | `send_timeout()` | `set_send_timeout(ms)`（非负校验） |

**设计要点：**

- 布尔选项统一用 `int` 0/1 传入内核（Linux 惯例）；
- 时间选项在 `std::chrono::milliseconds` 与 `struct timeval` 之间转换，避免用户直接操作 `timeval`；
- 缓冲区大小 `set_*` 校验非负，负值返回 `invalid_argument`。

### 4.9 组播接口

```cpp
int  multicast_ttl() const;
void set_multicast_ttl(int ttl);                       // 0..255
void join_multicast_group(const Address& group,
                          const Address& iface = Address{});
void leave_multicast_group(const Address& group,
                           const Address& iface = Address{});
void set_multicast_interface(const Address& iface);
void set_multicast_loop(bool on);
```

**设计要点：**

- 组播 TTL 校验 0~255；
- 组播加入/离开时，若 `iface` 为空则使用 `INADDR_ANY`；非 IPv4 地址通过 `to_in_addr` 返回 false 时置 `invalid_argument`，不进行选项设置。

### 4.10 关闭与半关闭

```cpp
void close() noexcept;          // 幂等；Linux 上 close EINTR 不重试
void shutdown_write();          // SHUT_WR
void shutdown_read();           // SHUT_RD
void shutdown_both();           // SHUT_RDWR
bool closed() const noexcept;   // fd_ < 0
int  fileno() const noexcept;   // 裸 fd，供 Selector / 用户直接用
Family family() const noexcept;
AddrType type() const noexcept;
```

**说明**：`close()` 中**不重试** `EINTR`——Linux 上 `close` 返回 `EINTR` 时 fd 实际可能已被释放，重试有风险，这是 POSIX 的已知陷阱。

`fileno()` 供 `Selector` 注册；`family()` / `type()` 供上层判断行为（如 `accept` 继承 `type_`）。

## 5. Selector 模块设计

### 5.1 Event 位掩码

```cpp
enum class Event : uint32_t {
    None   = 0,
    Read   = 1 << 0,
    Write  = 1 << 1,
    Error  = 1 << 2,
    Hangup = 1 << 3,

    EdgeTrigger = 1u << 16,   // 模式位，不参与事件匹配
};
```

**关键设计**：`Event::EdgeTrigger` 放在 bit 16，与低 8 位的事件位隔离。原因是 `has_event(set, e)` 只应判断"事件"，不应把模式位当成事件。为此提供：

```cpp
inline Event operator|(Event, Event);
inline Event operator&(Event, Event);
inline bool has_event(Event set, Event e);
inline Event event_bits(Event e);           // 屏蔽高 24 位，只保留低 8 位事件
inline bool  has_edge_trigger(Event e);     // 检测 ET
```

**位域划分：**

- 低 8 位（`0x00~0xFF`）：纯事件位，由内核报告；
- 高位（`1 << 16` 起）：模式位，仅作注册标志，**不会被报告**。

**为什么 ET 也是 Event 的 bit**：让用户可以用 `Event::Read | Event::EdgeTrigger` 一次表达 "读 + 边缘触发"，`Selector::add` 一个参数搞定，无需额外 API。语义上 ET 确实是 epoll 注册参数的一部分，作为 Event 的扩展位合理。

### 5.2 事件转换对照

| unpsock | select | poll | epoll |
|---------|--------|------|-------|
| `Read` | `readfds` | `POLLIN` / `POLLPRI` | `EPOLLIN` / `EPOLLPRI` |
| `Write` | `writefds` | `POLLOUT` | `EPOLLOUT` |
| `Error` | `exceptfds` | `POLLERR` / `POLLNVAL` | `EPOLLERR` |
| `Hangup` | — | `POLLHUP` | `EPOLLHUP` |
| `EdgeTrigger` | 忽略 | 忽略 | `EPOLLET` |

### 5.3 Selector 抽象接口

```cpp
class Selector {
public:
    virtual ~Selector() = default;
    virtual bool supports_edge_trigger() const noexcept { return false; }

    // 四个公有封装（异常版 + 错误码版 × 3 个操作 + wait）
    void add(int fd, Event events);
    void add(int fd, Event events, std::error_code& ec);
    void modify(int fd, Event events);
    void modify(int fd, Event events, std::error_code& ec);
    void remove(int fd);
    void remove(int fd, std::error_code& ec);

    std::vector<ReadyEvent> wait(std::optional<std::chrono::milliseconds> = std::nullopt);
    std::vector<ReadyEvent> wait(std::optional<std::chrono::milliseconds>, std::error_code& ec);

    // Socket 重载（转 fileno() 后调上面的）
    void add(const Socket&, Event);
    void add(const Socket&, Event, std::error_code&);
    void modify(const Socket&, Event);
    void modify(const Socket&, Event, std::error_code&);
    void remove(const Socket&);
    void remove(const Socket&, std::error_code&);

private:
    virtual void add_impl(int, Event, std::error_code&) = 0;
    virtual void modify_impl(int, Event, std::error_code&) = 0;
    virtual void remove_impl(int, std::error_code&) = 0;
    virtual std::vector<ReadyEvent> wait_impl(std::optional<std::chrono::milliseconds>,
                                              std::error_code&) = 0;
};
```

**NVI 模式**：公有非虚接口负责异常/错误码双风格转换，私有虚接口是纯错误码版——子类实现只需写一份逻辑。`add(const Socket&)` 重载免去调用者手动 `fileno()`。

**`supports_edge_trigger()`**：供上层查询后端能力，默认 `false`（select/poll 不支持 ET），epoll 覆写为 `true`。

**`wait` 的超时语义**：

- `std::nullopt` → 永久阻塞
- `0ms` → 非阻塞轮询
- `> 0` → 超时返回空 vector（`ec` 为空，与出错区分）

### 5.4 ReadyEvent

```cpp
struct ReadyEvent {
    int   fd;
    Event events;   // 只含 Read/Write/Error/Hangup，不含 EdgeTrigger
};
```

`wait()` 返回 `vector<ReadyEvent>`，调用方按顺序处理。不做 fd → 回调的分发，保持库的"零框架"定位。只包含实际就绪的 fd，未就绪的不出现，简化调用者遍历。

### 5.5 后端选择策略

库不强制用户用哪个后端，但提供工厂契约：

```cpp
std::unique_ptr<Selector> make_select_selector();
std::unique_ptr<Selector> make_select_selector(std::error_code&);
std::unique_ptr<Selector> make_poll_selector();
std::unique_ptr<Selector> make_poll_selector(std::error_code&);
std::unique_ptr<Selector> make_epoll_selector();
std::unique_ptr<Selector> make_epoll_selector(std::error_code&);   // 可能失败
```

- select/poll 无初始化失败可能，`ec` 版本仅为接口统一而存在；
- epoll 需要创建内核 epoll 实例，失败时返回 `nullptr` 并置 `ec`，调用者可据此判断 `BackendUnavailable`。

### 5.6 select 后端

**数据结构**：有序 fd → Event 映射（便于遍历时取最大 fd）。

**注册/修改/移除**：仅操作内存映射，`wait` 时动态构造 fd 集合。

**wait 实现：**

1. 遍历映射，按事件位设置读/写集合；
2. **总是**把所有 fd 加入异常集合（select 的异常集合对应错误/带外数据）；
3. `timeout` 转换为 `struct timeval`（毫秒 → 秒+微秒）；
4. 执行 select，`EINTR` 重试；
5. 遍历映射，用就绪判断收集事件，异常集合命中映射为 `Event::Error`。

**约束**：fd 超出 `FD_SETSIZE` 的注册应在 `add` 时拒绝（`wait` 中再次跳过，防御性）；不支持 ET（`supports_edge_trigger` 默认 false）。

### 5.7 poll 后端

**数据结构**：无序 fd → Event 映射（`wait` 时整体构造 pollfd 数组）。

**wait 实现：**

1. 遍历映射，构造 pollfd 数组，按事件位设置 events；
2. `timeout_ms` 为 -1（无限等待）或毫秒数；
3. 执行 poll，`EINTR` 重试；
4. 遍历返回的 pollfd，`revents != 0` 的构造 `ReadyEvent`。

**事件映射：**

| `Event` | `poll` |
|---------|--------|
| Read | `POLLIN` / `POLLPRI` |
| Write | `POLLOUT` |
| Error | `POLLERR` / `POLLNVAL` |
| Hangup | `POLLHUP` |

`POLLERR` / `POLLHUP` 无需显式请求，`poll` 总会报告。

**无 fd 数量上限**，但每次 `wait` 需 O(n) 重建数组；不支持 ET。

### 5.8 epoll 后端

**数据结构**：内核 epoll 实例 fd（创建时带 close-on-exec 语义）+ 内存映射（记录注册的事件，便于 `modify` 复用）。

**初始化双模式：**

- 异常版：失败抛 `SelectorError`；
- 错误码版：失败返回 false 并置 `ec`；
- 构造后为「未初始化」状态，`init` 幂等（已初始化直接返回 true）；
- 所有操作入口检查初始化状态，未初始化返回 `EBADF`。

**add**：

1. 校验 fd 合法、未注册；
2. 构造内核事件结构（含 `to_epoll(events)` 转换，ET 模式位映射为 `EPOLLET`）；
3. 调用内核注册接口；
4. 成功后记录到内存映射。

**modify**：校验已注册 → 调用内核修改接口 → 更新映射。

**remove**：校验已注册 → 调用内核删除接口（旧内核不接受空参数，需传 dummy）→ 擦除映射。

**wait 实现：**

1. 栈上固定大小事件数组（单次最多返回 N 个，常见取 64）；
2. `timeout_ms` 为 -1（无限等待）或 `count()`（≤0 时置 0）；
3. 调用内核等待接口，`EINTR` 重试；
4. `n == 0` 返回空 vector（超时）；`n < 0` 置 `ec`；
5. 遍历事件数组，转换事件位。

**事件映射：**

| `Event` | `epoll` |
|---------|---------|
| Read | `EPOLLIN` / `EPOLLPRI` |
| Write | `EPOLLOUT` |
| Error | `EPOLLERR` |
| Hangup | `EPOLLHUP` |
| EdgeTrigger（模式位） | `EPOLLET` |

转换时通过 `has_edge_trigger(e)` 决定是否附加 ET 标志，使得同一 `add` 接口可以表达 ET 注册需求。

**未处理 `EPOLLRDHUP`**：需显式注册才报告，当前库未暴露，保持最小行为集。

**`supports_edge_trigger()` 返回 `true`**。

## 8. 典型使用场景

### 8.1 TCP 服务端（epoll ET）

```cpp
unpsock::Socket listen_sock(unpsock::Family::INET, unpsock::AddrType::STREAM);
listen_sock.set_reuse_addr(true);
listen_sock.bind(unpsock::Address::any(8080));
listen_sock.listen(128);
listen_sock.set_nonblocking(true);

auto sel = unpsock::make_epoll_selector(ec);
sel->add(listen_sock, unpsock::Event::Read | unpsock::Event::EdgeTrigger);

while (running) {
    for (auto& ev : sel->wait(std::chrono::milliseconds(100))) {
        if (ev.fd == listen_sock.fileno()) {
            auto [conn, peer] = listen_sock.accept(ec);
            if (!ec) {
                conn.set_nonblocking(true);
                sel->add(conn, unpsock::Event::Read | unpsock::Event::EdgeTrigger);
            }
        }
    }
}
```

### 8.2 TCP 客户端（带超时）

```cpp
unpsock::Socket sock(unpsock::Family::INET, unpsock::AddrType::STREAM);
sock.connect_timed("example.com", 80, std::chrono::seconds(3), ec);
if (!ec) sock.sendall("GET / HTTP/1.1\r\n\r\n");
```

### 8.3 UDP 组播接收

```cpp
unpsock::Socket sock(unpsock::Family::INET, unpsock::AddrType::DGRAM);
sock.set_reuse_addr(true);
sock.bind(unpsock::Address::any(5353));
sock.join_multicast_group(unpsock::Address::from_ip("239.255.0.1", 5353));

```

## 9. 设计权衡与已知限制

### 9.1 设计权衡

| 决策 | 理由 |
|------|------|
| header-only 交付 | 零编译依赖、易集成；代价是包含该库的 TU 编译时间略增 |
| 双模式错误处理 | 覆盖异常禁用（`-fno-exceptions`）与高频路径（避免异常开销）两种场景 |
| `sockaddr_storage` 而非 `sockaddr` | 统一容器，避免族相关的内存管理 |
| `family_` 冗余字段 | 避免频繁 reinterpret，同时作为 `empty()` 判定依据 |
| `accept` 保留阻塞 | 非阻塞语义由调用者组合 `Selector` 使用，保持 API 正交 |
| select/poll 不缓存 fd 集合 | 简单优先；高频场景应选 epoll |
| epoll 未实现 `EPOLLRDHUP` | 需显式注册且语义易混淆，保持最小行为集 |
| `close` 不重试 EINTR | 遵循 Linux `close(2)` 陷阱文档 |
| 无 SSL/TLS、无线程池 | 专注 POSIX Socket 层，上层能力由使用者叠加 |

### 9.2 已知限制

1. **仅 Linux/POSIX**：epoll、`MSG_NOSIGNAL`、`SO_REUSEPORT` 等为 Linux 特性（`SO_REUSEPORT` 在部分 BSD 亦有）。
2. **epoll `wait` 单次上限 64**：超过需多次 `wait`，是常见做法但非硬性；若压测发现瓶颈可暴露事件数组容量配置。
3. **`select` 受 `FD_SETSIZE` 限制**：`add` 时未显式拒绝大 fd，`wait` 中跳过，行为为「不报告」，调用者应自行避免。
4. **`recvfrom` / `sendto` 无 `MSG_*` flags 参数**：当前固定 flags=0，若需 `MSG_PEEK` 等需扩展。
5. **创建 socket 未带 close-on-exec 标志**：子进程继承场景需手动设置；epoll 实例创建已带 close-on-exec 语义。
6. **`resolve_all` 遇部分地址转换失败静默跳过**：未知族地址不进入结果，调用者需注意结果数量可能少于原始链表长度。
7. **Unix Domain 相等性按定长比较**：路径语义上等价，但若两个 `sun_path` 尾部垃圾字节不同（理论上构造时会清零，实际不会）则不等；当前实现安全。

### 9.3 后续可扩展方向

- 增加 socket 创建时的 close-on-exec / non-blocking 标志选项；
- 增加 kqueue 后端以支持 BSD/macOS；
- `Selector::wait` 支持用户自定义回调或迭代器以降低分配；
- 增加 `recvmsg` / `sendmsg` 支持 `sendmmsg` 批量发送；
- 增加 `shutdown` 之后的状态查询封装；
- 提供基于 `Selector` 的简单 Reactor 示例类（非库职责，但可作为扩展或示例代码）。
