# unpsock C++ Socket 库详细设计文档

## 1. 概述

### 1.1 库简介

`unpsock` 是一个面向 Linux 平台的轻量级 C++11/14 Socket 网络库，提供 POSIX Socket 的现代 C++ 封装。库覆盖 TCP/UDP、IPv4/IPv6、Unix Domain Socket，支持三种 I/O 多路复用后端（select/poll/epoll），并通过统一的错误处理机制（异常版 + `std::error_code` 版）兼顾易用性与高性能场景需求。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| **POSIX 亲和** | 底层完全基于 Linux/POSIX Socket API，行为可预测，不引入额外抽象层 |
| **双模式错误处理** | 每个 API 同时提供「抛异常」和「输出 `std::error_code`」两种重载，便于在异常禁用或实时性敏感的代码中使用 |
| **RAII 资源管理** | `Socket` 对象持有一个 fd，遵循 Rule of Five：禁止拷贝、支持移动，析构自动关闭 |
| **后端可插拔** | `Selector` 抽象基类统一 select/poll/epoll 接口，运行期可替换 |
| **类型安全** | 通过 `Family`/`AddrType`/`Event` 等强类型枚举替代裸 `int`，减少误用 |
| **header-only** | 全部实现以 `inline`/模板形式置于头文件，零编译依赖，便于集成 |

### 1.3 模块组成

```
unpsock/
├── socket.hpp              // 聚合头文件（一站式包含）
├── socket_exception.hpp    // 异常体系 + getaddrinfo 错误类别
├── socket_host.hpp         // 本机主机名查询
├── socket_address.hpp      // 地址封装 Address
├── socket_socket.hpp       // 核心 Socket 类
├── socket_selector.hpp     // Selector 抽象接口 + Event 定义
├── socket_select.hpp       // select 后端
├── socket_poll.hpp         // poll 后端
└── socket_epoll.hpp        // epoll 后端
```

模块依赖关系（自底向上）：

```
socket_exception
      ↑
socket_address ──→ socket_socket ──→ socket_selector ──┬─→ socket_select
      ↑                                               ├─→ socket_poll
socket_host                                           └─→ socket_epoll
                                                      
socket.hpp  ←── 聚合以上全部
```

## 2. 通用约定

### 2.1 命名空间与命名风格

- 全部符号位于 `namespace unpsock`，内部辅助位于 `unpsock::detail`。
- 类型使用 `PascalCase`（`Address`、`Socket`、`EpollSelector`），函数/方法使用 `snake_case`（`from_ip`、`sendall`），成员变量后缀下划线（`fd_`、`storage_`）。
- 每个模块头文件使用 `#pragma once`。

### 2.2 双模式错误处理规范

所有可能失败的公开操作遵循统一模式：

```cpp
// 异常版：失败抛 SocketException 派生异常
ReturnType op(args...);

// 错误码版：失败通过 ec 输出，函数本身不抛
ReturnType op(args..., std::error_code& ec) noexcept;
```

约定细则：

1. 错误码版**总是先 `ec.clear()`**，成功时 `ec` 为空。
2. 异常版内部调用错误码版，若 `ec` 非空则抛出对应异常，保证两版行为一致。
3. 错误码版标记 `noexcept`（除极少数底层调用如 `std::vector` 分配可能抛 `bad_alloc` 外，逻辑上不抛）。
4. 返回类型为「值」的错误码版，失败时返回**默认构造值**（如 `Address{}`、空 `vector`、0）。

### 2.3 错误类别划分

| 错误源 | `error_category` | 构造方式 |
|--------|------------------|----------|
| 系统调用 errno | `std::system_category()` | `std::error_code(errno, std::system_category())` |
| `std::errc` 通用语义 | `std::generic_category()` | `std::make_error_code(std::errc::xxx)` |
| `getaddrinfo` 返回值 | 自定义 `gai_category` | `make_gai_error_code(rc)` |
| Selector 内部错误 | 自定义 `selector_category` | `make_selector_ec(SelectorErrc::xxx)` |

## 3. 异常体系设计（socket_exception.hpp）

### 3.1 类层次

```
std::system_error
      ↑
 SocketException                 (库异常基类)
      ↑
      ├── AddressError            (地址解析/构造失败)
      ├── SocketError             (socket 系统调用失败)
      └── SelectorError           (Selector 操作失败，定义于 socket_selector.hpp)
```

### 3.2 SocketException

```cpp
class SocketException : public std::system_error {
    SocketException(int errnum, const std::string& what);
    SocketException(std::error_code ec, const std::string& what);
    int errnum() const noexcept;      // 错误码数值
    std::string errmsg() const;       // 错误描述
};
```

继承 `std::system_error` 以复用 `what()` 与 `code()`，同时提供 `errnum()`/`errmsg()` 便捷访问。

### 3.3 getaddrinfo 错误类别

`getaddrinfo` 返回的是 EAI_* 码，与 errno 语义不同，因此自定义 `GaiCategory`：

```cpp
inline const std::error_category& gai_category() noexcept;   // 单例
inline std::error_code make_gai_error_code(int ev) noexcept;
```

`message(int)` 委托给 `::gai_strerror`。这样 DNS 解析失败的 `error_code` 能被 `std::error_code` 通用机制正确打印。

### 3.4 构造函数重载语义

`AddressError` 同时支持两种构造：

- `AddressError(what, gai_errnum)`：`gai_errnum` 默认 0，适用于 errno/ec 场景。
- `AddressError(ec, what)`：直接携带任意 `error_code`（含 `gai_category`）。

## 4. 地址模块设计（socket_address.hpp）

### 4.1 设计职责

`Address` 是 `struct sockaddr_storage` 的 RAII 封装，承担：

- 统一承载 IPv4、IPv6、Unix Domain 三类地址；
- 提供强类型构造（`from_ip` / `from_unix` / `from_sockaddr`）；
- 提供 DNS 解析（`resolve` / `resolve_all`）；
- 提供常用地址快捷构造（`any` / `loopback`）；
- 提供字符串化（`ip` / `to_string`）；
- 提供与底层 API 互操作（`sockaddr_ptr` / `sockaddr_len` / `to_storage`）。

### 4.2 内部表示

```cpp
struct sockaddr_storage storage_{};   // 最大 128 字节，容纳所有地址族
socklen_t len_ = 0;                   // 实际有效长度
Family family_ = Family::UNSPEC;      // 冗余保存族信息，便于快速分派
```

`family_` 与 `storage_.ss_family` 冗余但保持一致，避免每次重新解释 `storage_` 的头字段。

### 4.3 枚举定义

```cpp
enum class Family { INET, INET6, UNIX, UNSPEC };
enum class AddrType { STREAM, DGRAM };
```

`detail::to_af` / `from_af` / `to_socktype` 完成与系统常量（`AF_INET` 等）的双向映射，默认 `UNSPEC` 用于「未指定/自动判定」。

### 4.4 构造 API

| 方法 | 说明 |
|------|------|
| `from_ip(ip, port, family, [ec])` | 优先按 IPv4 解析，失败再尝试 IPv6（`family=UNSPEC` 时）；`family` 指定时只尝试对应族 |
| `from_unix(path, [ec])` | 构造 Unix Domain 地址，`path` 超长返回 `filename_too_long` |
| `from_sockaddr(sa, len, [ec])` | 从底层 `sockaddr` 拷贝，`len` 超出 `storage_` 容量视为非法 |
| `any(port, family, [ec])` | `INADDR_ANY` / `in6addr_any`；`UNIX` 或 `UNSPEC` 返回 `invalid_argument` |
| `loopback(port, family, [ec])` | `INADDR_LOOPBACK` / `in6addr_loopback` |
| `resolve(host, port/serv, family, type, [ec])` | DNS 解析，返回首个结果 |
| `resolve_all(...)` | 返回全部结果 |

### 4.5 DNS 解析实现

基于 `getaddrinfo`：

```cpp
struct addrinfo hints{};
hints.ai_family = detail::to_af(family);
hints.ai_socktype = detail::to_socktype(type);
hints.ai_flags = AI_CANONNAME;
```

`host`/`serv` 为空时对应传 `nullptr`，符合 `getaddrinfo` 语义（可获取本机通配地址/服务名解析）。

结果通过 `detail::Guard`（局部结构体析构中 `freeaddrinfo`）保证释放；对每个 `ai_addr` 调用 `from_sockaddr_impl`，转换失败（如地址族未知）时静默跳过，不影响其余结果。

`resolve` 实现为取 `resolve_all().front()`；为空时报 `EAI_NONAME`。

### 4.6 字符串化语义

- `ip()`：仅返回地址部分。Unix 返回 `sun_path`，IPv4/IPv6 返回数字地址（`inet_ntop`），未知族返回空串。
- `to_string()`：
  - Unix → `path`
  - IPv6 → `[addr]:port`（RFC 3986 风格）
  - IPv4 → `addr:port`

### 4.7 比较与相等性

`operator==` 按族分别比较：

- IPv4：`sin_port` + `sin_addr.s_addr`
- IPv6：`sin6_port` + `sin6_addr`（`memcmp`）
- Unix：`memcmp` 整个 `sun_path` 定长数组（即使路径较短也按整段比较，语义上等价于「路径完全相同」）
- 其他：视为相等（`UNSPEC` 与其他 `UNSPEC` 相等）

`operator!=` 为 `!operator==`。

### 4.8 `to_in_addr` / `to_in6_addr`

仅当族匹配时输出并返回 `true`，否则返回 `false` 且**不修改**出参。此设计供上层组播等仅支持 IPv4 的接口安全调用。

### 4.9 SUN_LEN 兼容宏

`<sys/un.h>` 不保证提供 `SUN_LEN`，头文件内以 `#ifndef` 兜底定义，采用 4.4BSD 版本：

```c
#define SUN_LEN(su) \
    (sizeof(*(su)) - sizeof((su)->sun_path) + strlen((su)->sun_path))
```

`from_unix_impl` 中据此计算 `len_`，保证 `bind`/`connect` 时长度精确，避免路径后缀垃圾字节。

## 5. 核心 Socket 类设计（socket_socket.hpp）

### 5.1 类定义与生命周期

```cpp
class Socket {
    int fd_ = -1;
    Family family_ = Family::UNSPEC;
    AddrType type_ = AddrType::STREAM;
};
```

**Rule of Five 策略：**

| 操作 | 行为 |
|------|------|
| 默认构造 | `fd_ = -1`，无效句柄 |
| `Socket(Family, AddrType)` | 调用 `::socket` 创建，失败抛 `SocketError` |
| `Socket(int fd, Family, AddrType)` | 内部使用（`accept` 产生），直接接管 fd |
| 拷贝构造/赋值 | **删除**，防止双重关闭 |
| 移动构造/赋值 | 接管 fd，源置 `-1`/`UNSPEC` |
| 析构 | `close()`，幂等 |

`valid()` / `operator bool()` 判断 `fd_ >= 0`。

### 5.2 服务端 API

#### 5.2.1 bind

```cpp
void bind(const Address& addr, std::error_code& ec) noexcept;
```

直接转发 `::bind(fd_, addr.sockaddr_ptr(), addr.sockaddr_len())`，errno 转 `system_category`。异常版额外在 `what` 中拼接地址串，便于定位。

#### 5.2.2 listen

```cpp
void listen(int backlog, std::error_code& ec) noexcept;
```

转发 `::listen`，`backlog` 默认 5（POSIX 常见默认）。

#### 5.2.3 accept

```cpp
std::pair<Socket, Address> accept(std::error_code& ec) noexcept;
```

流程：

1. 循环调用 `::accept`，`EINTR` 时重试；
2. 失败 → `ec` 置位，返回 `{Socket{}, Address{}}`；
3. 成功 → 从 `sockaddr_storage` 构造 `Address`，返回 `{Socket(conn_fd, peer.family(), type_), peer}`。

返回值的 `Socket` 通过内部构造函数接管 fd，`type_` 沿用监听 socket 的类型（TCP/UDP）。

**设计说明**：`accept` 保留阻塞语义，非阻塞场景由调用者配合 `Selector` 使用——先 `Selector::add(listen_fd, Read)`，等可读后再 `accept`。

### 5.3 客户端 API

#### 5.3.1 connect(Address)

```cpp
void connect(const Address& addr, std::error_code& ec) noexcept;
```

`EINTR` 重试，失败置 `ec`。注意：`connect` 可能返回 `EINPROGRESS`（非阻塞），本函数不特殊处理，原样透出，调用者需结合非阻塞语义判断。

#### 5.3.2 connect(host, port)

```cpp
void connect(const std::string& host, uint16_t port, std::error_code& ec) noexcept;
```

先 `Address::resolve(host, port, family_, type_, ec)`，成功后再 `connect(addr)`。`ec` 可能来自 `gai_category`（解析失败）或 `system_category`（连接失败），两种均可被 `SocketError` 携带。

#### 5.3.3 connect_timed（带超时连接）

非阻塞 connect + `select` 等待可写，是库中唯一独立实现的超时连接逻辑。

**实现步骤：**

1. **保存并设置非阻塞**：`fcntl(F_GETFL)` 取旧标志，`F_SETFL` 置 `O_NONBLOCK`。
2. **恢复守卫**：局部 `FlagsGuard` 在析构时恢复旧标志，保证任何返回路径（含异常）都不残留非阻塞状态。
3. **发起非阻塞 connect**：
   - 返回 0 → 立即成功（localhost 常见）；
   - `errno != EINPROGRESS` → 失败透出；
   - `EINPROGRESS` → 继续。
4. **select 等待**：`rset`/`wset` 同时监听（连接失败时 fd 可读），`EINTR` 重试。
   - `n < 0` → errno 透出；
   - `n == 0` → `std::errc::timed_out`。
5. **SO_ERROR 取真实结果**：`getsockopt(SOL_SOCKET, SO_ERROR)`，非 0 则作为错误透出。

**注意点**：`struct timeval` 在 `select` 返回后可能被内核修改，故每次调用前重新构造（本实现每次进入函数都新建 `tv`，天然满足）。`FlagsGuard` 恢复在成功路径与失败路径均执行，保证语义一致。

### 5.4 数据收发

#### 5.4.1 recv 两个重载

```cpp
std::vector<uint8_t> recv(size_t bufsize, std::error_code& ec) noexcept;
size_t recv(void* buf, size_t bufsize, std::error_code& ec) noexcept;
```

- vector 版：内部 buffer `resize(n)` 到实际字节数；
- 指针版：返回实际字节数。

**统一语义**：

- `n == 0`：对端关闭，`ec` 为空，返回 0（或空 vector）；
- `n > 0`：正常；
- `n < 0`：`ec` 非空，返回 0（或空 vector）。

`recv_impl` 内部处理 `EINTR` 重试。

#### 5.4.2 send / sendall

| 函数 | 语义 |
|------|------|
| `send` | 单次 `::send`，可能短写，返回实际发送字节数 |
| `sendall` | 循环发送直到全部发出或出错，返回已发送字节数 |

两者均使用 `MSG_NOSIGNAL`，避免 SIGPIPE 杀死进程。`sendall` 中 `EINTR` 重试，短写继续循环。

返回「已发送字节数」而非 bool，是为了在部分发送失败时调用者能准确知道进度（尤其 `sendall` 失败时）。

#### 5.4.3 recvfrom / sendto（UDP）

```cpp
std::pair<std::vector<uint8_t>, Address> recvfrom(size_t bufsize, std::error_code& ec) noexcept;
size_t sendto(const void* data, size_t len, const Address& addr, std::error_code& ec) noexcept;
```

- `recvfrom` 返回（数据，对端地址）二元组，对端地址由 `sockaddr_storage` 转换；
- `sendto` 使用 `Address` 的 `sockaddr_ptr()`/`sockaddr_len()`，`EINTR` 重试。

### 5.5 查询 API

#### 5.5.1 getsockname / getpeername

```cpp
Address getsockname(std::error_code& ec) const noexcept;
Address getpeername(std::error_code& ec) const noexcept;
```

`const` 成员，因为不修改 socket 状态。失败返回 `Address{}`。

### 5.6 非阻塞开关

```cpp
void set_nonblocking(bool enable, std::error_code& ec) noexcept;
bool is_nonblocking(std::error_code& ec) const noexcept;
```

`fcntl(F_GETFL)` → 按需置/清 `O_NONBLOCK` → `fcntl(F_SETFL)`。`is_nonblocking` 返回 `(flags & O_NONBLOCK) != 0`。

### 5.7 选项模板接口

```cpp
template <typename T> T getsockopt(int level, int optname, std::error_code& ec) const noexcept;
template <typename T> void setsockopt(int level, int optname, const T& value, std::error_code& ec) noexcept;
```

- `T` 必须为 POD（`int`、`struct linger`、`struct timeval`、`unsigned char`、`struct in_addr`、`struct ip_mreq` 等）；
- `getsockopt<T>` 通过 `len` 出参校验：若内核返回的长度不等于 `sizeof(T)`，视为 `invalid_argument`，防止结构体版本不匹配导致的脏读；
- `setsockopt` 直接传 `&value` 与 `sizeof(T)`。

### 5.8 常用选项便捷封装

以下选项均提供「异常版 + 错误码版 + getter/setter」全套：

| 选项 | getter | setter | 类型 |
|------|--------|--------|------|
| `SO_REUSEADDR` | `reuse_addr()` | `set_reuse_addr(bool)` | bool |
| `SO_REUSEPORT` | `reuse_port()` | `set_reuse_port(bool)` | bool |
| `SO_KEEPALIVE` | `keep_alive()` | `set_keep_alive(bool)` | bool |
| `TCP_NODELAY` | `tcp_nodelay()` | `set_tcp_nodelay(bool)` | bool |
| `SO_BROADCAST` | `broadcast()` | `set_broadcast(bool)` | bool |
| `SO_RCVBUF` | `recv_buffer_size()` | `set_recv_buffer_size(int)` | int |
| `SO_SNDBUF` | `send_buffer_size()` | `set_send_buffer_size(int)` | int |
| `SO_LINGER` | `linger_opt()` | `set_linger(bool, int)` | struct linger |
| `SO_RCVTIMEO` | `recv_timeout()` | `set_recv_timeout(ms)` | timeval ↔ milliseconds |
| `SO_SNDTIMEO` | `send_timeout()` | `set_send_timeout(ms)` | timeval ↔ milliseconds |
| `IP_MULTICAST_TTL` | `multicast_ttl()` | `set_multicast_ttl(int)` | unsigned char（0~255） |
| `IP_MULTICAST_LOOP` | — | `set_multicast_loop(bool)` | unsigned char |
| `IP_MULTICAST_IF` | — | `set_multicast_interface(Address)` | struct in_addr |
| `IP_ADD_MEMBERSHIP` | — | `join_multicast_group(group, iface)` | struct ip_mreq |
| `IP_DROP_MEMBERSHIP` | — | `leave_multicast_group(group, iface)` | struct ip_mreq |

**设计要点：**

- 布尔选项统一用 `int` 0/1 传入内核（Linux 惯例）；
- 时间选项在 `std::chrono::milliseconds` 与 `struct timeval` 之间转换，避免用户直接操作 `timeval`；
- 缓冲区大小 `set_*` 校验非负，负值返回 `invalid_argument`；
- 组播 TTL 校验 0~255；
- 组播加入/离开时，若 `iface` 为空则使用 `INADDR_ANY`；非 IPv4 地址通过 `to_in_addr` 返回 false 时置 `invalid_argument`，不进行 `setsockopt`。

### 5.9 关闭与半关闭

| 方法 | 行为 |
|------|------|
| `close()` | `fd_ >= 0` 时 `::close` 并置 `-1`，幂等，`noexcept` |
| `shutdown_write()` | `SHUT_WR` |
| `shutdown_read()` | `SHUT_RD` |
| `shutdown_both()` | `SHUT_RDWR` |
| `closed()` | `fd_ < 0` |

**说明**：`close()` 中**不重试** `EINTR`——Linux 上 `close` 返回 `EINTR` 时 fd 实际可能已被释放，重试有风险，这是 POSIX 的已知陷阱。

### 5.10 fd 暴露

```cpp
int fileno() const noexcept;
Family family() const noexcept;
AddrType type() const noexcept;
```

`fileno()` 供 `Selector` 注册；`family()`/`type()` 供上层判断行为（如 `accept` 继承 `type_`）。

## 6. I/O 多路复用设计

### 6.1 Event 事件模型（socket_selector.hpp）

```cpp
enum class Event : uint32_t {
    None   = 0,
    Read   = 1 << 0,
    Write  = 1 << 1,
    Error  = 1 << 2,
    Hangup = 1 << 3,

    EdgeTrigger = 1u << 16,   // 模式位
};
```

**位域划分：**

- 低 8 位（`0x00~0xFF`）：纯事件位，由内核报告；
- 高位（`1 << 16` 起）：模式位，仅作注册标志，**不会被报告**。

配套工具函数：

```cpp
Event operator|(Event, Event);
Event operator&(Event, Event);
bool has_event(Event set, Event e);
Event event_bits(Event e);          // 仅保留低 8 位
bool has_edge_trigger(Event e);
```

`ReadyEvent` 结构：

```cpp
struct ReadyEvent { int fd; Event events; };
```

`wait` 返回 `std::vector<ReadyEvent>`，只包含实际就绪的 fd，未就绪的不出现，简化调用者遍历。

### 6.2 SelectorErrc 与 selector_category

```cpp
enum class SelectorErrc {
    Success = 0,
    AlreadyRegistered,   // add 时 fd 已注册
    NotRegistered,       // modify/remove 时 fd 未注册
    BackendUnavailable,  // 构造后端失败
    WaitFailed,          // wait 底层失败
};
```

`SelectorErrorCategory` 实现 `name()`/`message()`，`make_selector_ec` 构造 `error_code`。错误信息为英文短语，便于日志检索。

### 6.3 Selector 抽象接口

```cpp
class Selector {
public:
    virtual ~Selector() = default;
    virtual bool supports_edge_trigger() const noexcept;   // 默认 false

    // 双模式：add / modify / remove / wait
    void add(int fd, Event events);
    void add(int fd, Event events, std::error_code& ec);
    void modify(int fd, Event events);
    void modify(int fd, Event events, std::error_code& ec);
    void remove(int fd);
    void remove(int fd, std::error_code& ec);
    std::vector<ReadyEvent> wait(std::optional<std::chrono::milliseconds> timeout = std::nullopt);
    std::vector<ReadyEvent> wait(std::optional<std::chrono::milliseconds> timeout, std::error_code& ec);

    // 便捷重载：直接传 Socket
    void add(const Socket& s, Event events);
    void add(const Socket& s, Event events, std::error_code& ec);
    // modify/remove 同理

private:
    virtual void add_impl(int fd, Event events, std::error_code& ec) = 0;
    virtual void modify_impl(int fd, Event events, std::error_code& ec) = 0;
    virtual void remove_impl(int fd, std::error_code& ec) = 0;
    virtual std::vector<ReadyEvent> wait_impl(
        std::optional<std::chrono::milliseconds>, std::error_code&) = 0;
};
```

**模板方法模式**：公开接口统一处理「异常/错误码」两种形态，实际后端逻辑在 `*_impl` 中实现。`add(const Socket&)` 重载免去调用者手动 `fileno()`。

**`supports_edge_trigger()`**：供上层查询后端能力，默认 `false`（select/poll 不支持 ET），epoll 覆写为 `true`。

### 6.4 select 后端（socket_select.hpp）

**数据结构**：`std::map<int, Event> map_`（有序，便于遍历时取最大 fd）。

**add/modify/remove**：仅操作 `map_`，`wait` 时动态构造 fd_set。

**wait 实现：**

1. 遍历 `map_`，按事件位设置 `readfds`/`writefds`；
2. **总是**把所有 fd 加入 `exceptfds`（select 的异常集合对应错误/带外数据）；
3. `timeout` 转换为 `struct timeval`（毫秒 → 秒+微秒）；
4. `select` 调用，`EINTR` 重试；
5. 遍历 `map_`，用 `FD_ISSET` 收集就绪事件，`exceptfds` 命中映射为 `Event::Error`。

**约束**：`fd >= FD_SETSIZE` 的 fd 在 `add` 时应拒绝（代码在 `wait` 中再次跳过，防御性）；不支持 ET（`supports_edge_trigger` 默认 false）。

### 6.5 poll 后端（socket_poll.hpp）

**数据结构**：`std::unordered_map<int, Event> map_`（无序，`wait` 时整体构造 `pollfd` 数组）。

**wait 实现：**

1. 遍历 `map_`，构造 `std::vector<struct pollfd>`，`events = to_poll(ev)`；
2. `timeout_ms = timeout ? timeout->count() : -1`；
3. `poll` 调用，`EINTR` 重试；
4. 遍历返回的 `pollfd`，`revents != 0` 的构造 `ReadyEvent`。

**事件映射：**

| `Event` | `poll` |
|---------|--------|
| Read | `POLLIN` / `POLLPRI` |
| Write | `POLLOUT` |
| Error | `POLLERR` / `POLLNVAL` |
| Hangup | `POLLHUP` |

`POLLERR`/`POLLHUP` 无需显式请求，`poll` 总会报告。

**无 fd 数量上限**，但每次 `wait` 需 O(n) 重建数组；不支持 ET。

### 6.6 epoll 后端（socket_epoll.hpp）

**数据结构**：`int epfd_`（由 `epoll_create1(EPOLL_CLOEXEC)` 创建）+ `std::unordered_map<int, Event> map_`。

**init 双模式：**

- `void init()`：失败抛 `SelectorError`；
- `bool init(std::error_code& ec)`：失败返回 false；
- 构造时 `epfd_ = -1`，`init` 幂等（已初始化直接返回 true）；
- `check_init` 在 `add/modify/remove/wait` 入口调用，未初始化返回 `EBADF`。

**add**：

1. 校验 fd 合法、未注册；
2. 构造 `epoll_event{events=to_epoll(events), data.fd=fd}`；
3. `epoll_ctl(EPOLL_CTL_ADD)`；
4. 成功后记录到 `map_`。

**modify**：校验已注册 → `EPOLL_CTL_MOD` → 更新 `map_`。

**remove**：校验已注册 → `EPOLL_CTL_DEL`（传入 dummy `epoll_event`，兼容旧内核不接受 `nullptr`）→ 擦除。

**wait 实现：**

1. 栈上 `epoll_event evs[64]`，单次最多返回 64 个；
2. `timeout_ms` 为 -1（无限等待）或 `count()`（≤0 时置 0）；
3. `epoll_wait`，`EINTR` 重试；
4. `n == 0` 返回空 vector（超时）；`n < 0` 置 `ec`；
5. 遍历 `evs[0..n)`，`from_epoll` 转换事件。

**事件映射：**

| `Event` | `epoll` |
|---------|---------|
| Read | `EPOLLIN` / `EPOLLPRI` |
| Write | `EPOLLOUT` |
| Error | `EPOLLERR` |
| Hangup | `EPOLLHUP` |
| EdgeTrigger（模式位） | `EPOLLET` |

`to_epoll` 中通过 `has_edge_trigger(e)` 决定是否附加 `EPOLLET`，使得同一 `add` 接口可以表达 ET 注册需求。

**未处理 `EPOLLRDHUP`**：需显式注册才报告，当前库未暴露，保持最小行为集。

**`supports_edge_trigger()` 返回 `true`**。

### 6.7 后端工厂函数

```cpp
std::unique_ptr<Selector> make_select_selector();
std::unique_ptr<Selector> make_select_selector(std::error_code& ec);
std::unique_ptr<Selector> make_poll_selector();
std::unique_ptr<Selector> make_poll_selector(std::error_code& ec);
std::unique_ptr<Selector> make_epoll_selector(std::error_code& ec);
```

- select/poll 无初始化失败可能，`ec` 版本仅为接口统一而存在；
- epoll 需要 `epoll_create1`，失败时返回 `nullptr` 并置 `ec`，调用者可据此判断 `BackendUnavailable`。

## 9. 典型使用场景

### 9.1 TCP 服务端（epoll ET）

```cpp
unpsock::Socket listen_sock(unpsock::Family::INET, unpsock::AddrType::STREAM);
listen_sock.set_reuse_addr(true);
listen_sock.bind(unpsock::Address::any(8080));
listen_sock.listen(128);
listen_sock.set_nonblocking(true);

auto sel = unpsock::make_epoll_selector(ec);
sel->add(listen_sock, unpsock::Event::Read | unpsock::Event::EdgeTrigger);

while (running) {
    for (auto& ev : sel->wait(std::chrono::milliseconds(100))) {
        if (ev.fd == listen_sock.fileno()) {
            auto [conn, peer] = listen_sock.accept(ec);
            if (!ec) {
                conn.set_nonblocking(true);
                sel->add(conn, unpsock::Event::Read | unpsock::Event::EdgeTrigger);
            }
        }
    }
}
```

### 9.2 TCP 客户端（带超时）

```cpp
unpsock::Socket sock(unpsock::Family::INET, unpsock::AddrType::STREAM);
sock.connect_timed("example.com", 80, std::chrono::seconds(3), ec);
if (!ec) sock.sendall("GET / HTTP/1.1\r\n\r\n");
```

## 10. 设计权衡与已知限制

### 10.1 设计权衡

| 决策 | 理由 |
|------|------|
| header-only | 零编译依赖、易集成；代价是包含头文件的 TU 编译时间略增 |
| 双模式错误处理 | 覆盖异常禁用（`-fno-exceptions`）与高频路径（避免异常开销）两种场景 |
| `sockaddr_storage` 而非 `sockaddr` | 统一容器，避免族相关的内存管理 |
| `family_` 冗余字段 | 避免频繁 reinterpret，同时作为 `empty()` 判定依据 |
| `accept` 保留阻塞 | 非阻塞语义由调用者组合 `Selector` 使用，保持 API 正交 |
| select/poll 不缓存 fd_set/pollfd | 简单优先；高频场景应选 epoll |
| epoll 未实现 `EPOLLRDHUP` | 需显式注册且语义易混淆，保持最小行为集 |
| `close` 不重试 EINTR | 遵循 Linux `close(2)` 陷阱文档 |
| 无 SSL/TLS、无线程池 | 专注 POSIX Socket 层，上层能力由使用者叠加 |

### 10.2 已知限制

1. **仅 Linux/POSIX**：`epoll`、`SUN_LEN`、`MSG_NOSIGNAL`、`SO_REUSEPORT` 等为 Linux 特性（`SO_REUSEPORT` 在部分 BSD 亦有）。
2. **epoll `wait` 单次上限 64**：超过需多次 `wait`，是常见做法但非硬性；若压测发现瓶颈可暴露 `MAX_EVENTS` 配置。
3. **`select` 受 `FD_SETSIZE` 限制**：`add` 时未显式拒绝大 fd，`wait` 中跳过，行为为「不报告」，调用者应自行避免。
4. **`recvfrom`/`sendto` 无 `MSG_*` flags 参数**：当前固定 flags=0，若需 `MSG_PEEK` 等需扩展。
5. **无 `SOCK_CLOEXEC`**：`::socket` 未传该标志，子进程继承场景需手动 `fcntl(FD_CLOEXEC)`；`epoll_create1(EPOLL_CLOEXEC)` 已带。
6. **`resolve_all` 遇部分 `ai_addr` 转换失败静默跳过**：未知族地址不进入结果，调用者需注意结果数量可能少于 `addrinfo` 链表长度。
7. **Unix Domain `operator==` 按定长比较**：路径语义上等价，但若两个 `sun_path` 尾部垃圾字节不同（理论上 `from_unix` 会清零，实际不会）则不等；当前实现安全。

### 10.3 后续可扩展方向

- 增加 `SOCK_CLOEXEC` / `SOCK_NONBLOCK` 创建标志选项；
- 增加 `kqueue` 后端以支持 BSD/macOS；
- `Selector::wait` 支持用户自定义回调或迭代器以降低分配；
- 增加 `recvmsg`/`sendmsg` 支持 `sendmmsg` 批量发送；
- 增加 `shutdown` 之后的状态查询封装；
- 提供基于 `Selector` 的简单 `Reactor` 示例类（非库职责，但可作为扩展或示例代码）。
