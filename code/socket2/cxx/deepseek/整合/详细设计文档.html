2. 错误处理设计

2.1 异常层次

std::system_error
  └── unpsock::SocketException          // 通用基类；持 std::error_code + what
        ├── unpsock::AddressError       // 地址解析 / DNS（默认 gai_category）
        ├── unpsock::SocketError        // 底层 socket syscall 失败
        └── unpsock::SelectorError      // Selector 注册 / wait 失败

关键点：

  • SocketException 继承 std::system_error，构造函数同时接受 int errnum 和 std::error_code。

  • AddressError 默认用 gai_category()，因为 getaddrinfo 的返回值属于 EAI_* 命名空间，不能映射到 errno。

  • SelectorError 同时覆盖两种来源：system_category（后端初始化失败）与 selector_category（AlreadyRegistered 等）。

SocketException 契约：

xxxxxxxxxx
class SocketException : public std::system_error {
    SocketException(int errnum, const std::string& what);
    SocketException(std::error_code ec, const std::string& what);
};

继承 std::system_error 以复用 what() 与 code()。

2.4 双风格约定（契约）

所有公有 API 遵循以下模式：

xxxxxxxxxx
// 异常版：无 error_code 出参，失败 throw
void op(Args...);
// 错误码版：error_code& 出参，noexcept，失败置 ec
void op(Args..., std::error_code& ec) noexcept;

约定细则：

  1. 错误码版总是先 ec.clear()，成功时 ec 为空。

  2. 异常版内部调用错误码版，再 if (ec) throw——这保证两条路径行为一致。

  3. 返回类型为「值」的错误码版，失败时返回默认构造值（如 Address{}、空 vector、0）。

  4. 异常版的 what 消息中应包含必要的上下文（如地址串 addr.to_string()），便于定位。

3. 地址模块设计（Address）

3.1 设计职责

Address 是 struct sockaddr_storage 的 RAII 值对象，承担：

  • 统一承载 IPv4、IPv6、Unix Domain 三类地址；

  • 提供强类型构造（from_ip / from_unix / from_sockaddr）；

  • 提供 DNS 解析（resolve / resolve_all）；

  • 提供常用地址快捷构造（any / loopback）；

  • 提供字符串化（ip / to_string）；

  • 提供与底层 API 互操作（sockaddr_ptr / sockaddr_len / to_storage）。

3.2 值语义

Address 采用完整值语义，可自由拷贝/赋值：

xxxxxxxxxx
Address() = default;
Address(const Address& other);            // 逐字段 + storage_ 整体拷贝
Address& operator=(const Address& other); // 自赋值保护
~Address() = default;

拷贝时按成员逐一赋值（storage_ 整体 memcpy、len_、family_），无需移动语义，因为其内部无资源所有权。

3.3 数据布局

xxxxxxxxxx
class Address {
    struct sockaddr_storage storage_;   // 128 字节，覆盖所有 sockaddr_*
    socklen_t               len_;       // 实际长度
    Family                  family_;    // 冗余家族标记，快速判断
};

统一存储的动机：Linux 上 sockaddr_storage 足以容纳 sockaddr_in（16B）、sockaddr_in6（28B）、sockaddr_un（110B）。使用 sockaddr_storage 作为唯一载体，避免 union + tag 的手工管理。

family_ 与 storage_.ss_family 冗余但保持一致，避免每次重新解释 storage_ 的头字段；同时作为 empty() 判定依据。

内部 clear() 私有方法将三字段重置为初始状态（storage_ 清零、len_ = 0、family_ = UNSPEC），所有 *_impl 内部实现在入口处调用它，保证构造失败时不残留脏数据。

3.4 枚举定义

detail::to_af / from_af / to_socktype 完成与系统常量（AF_INET 等）的双向映射，默认 UNSPEC 用于「未指定/自动判定」。

3.6 构造 API 矩阵

关键实现契约：

  • from_ip 的 family 参数决定尝试顺序：UNSPEC 时先 IPv4 再 IPv6，指定族时只尝试对应族；两种尝试都失败返回 invalid_argument。

  • 解析失败后 ec 被设为对应类别错误，返回的 Address 保持默认构造状态（empty() == true）。

  • resolve 与 resolve_all 有两族重载：uint16_t port 版内部转字符串委托给 std::string serv 版，避免重复实现。

3.7 字符串化

IPv6 用 [...] 包裹，符合 RFC 3986 host 语法。未知族返回空串。inet_ntop 失败时 ip() 返回空串（不抛异常，作为查询接口保持轻量）。

3.8 属性查询

3.9 比较与相等性

operator== 按族分别比较：

  • 族不同 → 不等；

  • IPv4：sin_port + sin_addr.s_addr；

  • IPv6：sin6_port + sin6_addr（memcmp）；

  • Unix：memcmp 整个 sun_path 定长数组（即使路径较短也按整段比较，语义上等价于「路径完全相同」）；

  • 其他（UNSPEC）：视为相等。

operator!= 为 !operator==。

3.10 to_in_addr / to_in6_addr

仅当族匹配时输出并返回 true，否则返回 false 且不修改出参。此设计供上层组播等仅支持 IPv4 的接口安全调用。

4.2 服务端 API

accept 流程：

  1. 循环调用 accept 系统调用，EINTR 时重试；

  2. 失败 → ec 置位，返回 {Socket{}, Address{}}；

  3. 成功 → 从 sockaddr_storage 构造 Address，返回 {Socket(conn_fd, peer.family(), type_), peer}。

返回值的 Socket 通过内部构造函数接管 fd，type_ 沿用监听 socket 的类型（TCP/UDP），family_ 取自 peer 地址。

设计说明：accept 保留阻塞语义，非阻塞场景由调用者配合 Selector 使用——先 Selector::add(listen_fd, Read)，等可读后再 accept。

4.3 客户端 API

4.3.1 connect 语义说明

connect 可能返回 EINPROGRESS（非阻塞），本函数不特殊处理，原样透出，调用者需结合非阻塞语义判断。EINTR 时在循环内重试。

4.3.2 connect_timed 实现

非阻塞 connect + select 等待可写，是库中唯一独立实现的超时连接逻辑。

实现步骤：

  1. 保存并设置非阻塞：fcntl(F_GETFL) 取旧标志，F_SETFL 置 O_NONBLOCK；任一步失败立即透出 errno。

  2. 恢复守卫：局部结构体 FlagsGuard 持有 {fd, old_flags}，析构时 F_SETFL 恢复旧标志，保证任何返回路径（含异常）都不残留非阻塞状态。

  3. 发起非阻塞 connect：

    • 返回 0 → 立即成功（localhost 常见）；

    • errno != EINPROGRESS → 失败透出；

    • EINPROGRESS → 继续。

  4. select 等待：读/写集合同时监听（连接失败时 fd 可读），EINTR 重试。

    • n < 0 → errno 透出；

    • n == 0 → std::errc::timed_out。

  5. SO_ERROR 取真实结果：通过 getsockopt<int>(SOL_SOCKET, SO_ERROR) 读取，非 0 则作为错误透出。

  6. 成功路径与失败路径均在离开函数时由守卫恢复原阻塞标志。

注意点：struct timeval 在 select 返回后可能被内核修改，故每次调用前必须重新构造（本实现通过 to_timeval 辅助函数每次新建）。恢复守卫保证语义一致。

便捷重载：connect_timed(host, port, timeout, ec) 先 Address::resolve，解析成功再委托给 connect_timed(addr, ...)；解析失败时直接返回，避免多余操作。

4.4 数据收发

统一语义（recv 两重载）：

  • n == 0：对端关闭，ec 为空，返回 0（或空 vector）；

  • n > 0：正常；

  • n < 0：ec 非空，返回 0（或空 vector）。

接收路径内部 recv_impl 处理 EINTR 重试。recv(size_t) 在 bufsize == 0 时返回 invalid_argument。

sendall 循环逻辑：

xxxxxxxxxx
size_t sent = 0;
while (sent < len) {
    ssize_t n = send(剩余数据, MSG_NOSIGNAL);
    if (n < 0) {
        if (errno == EINTR) continue;
        ec = std::error_code(errno, std::system_category());
        return sent;   // 部分发送，调用方需检查 ec 与返回值
    }
    sent += n;
}

返回「已发送字节数」而非 bool，是为了在部分发送失败时调用者能准确知道进度（尤其 sendall 失败时）。发送路径统一使用 MSG_NOSIGNAL 抑制 SIGPIPE（对端关闭时进程不应被信号杀死）。

send 单次语义：EINTR 重试，返回本次实际发送字节数，可能短写；不做循环。

recvfrom / sendto（UDP）：

  • recvfrom 使用栈上 sockaddr_storage 接收对端地址，成功后通过 Address::from_sockaddr 转换；

  • sendto 通过 Address 的 sockaddr_ptr() / sockaddr_len() 直接使用，EINTR 重试。

4.6 非阻塞开关

set_nonblocking(bool) / is_nonblocking() 通过 fcntl(F_GETFL / F_SETFL) 操作 O_NONBLOCK 位。is_nonblocking() 在 ec 非空时返回 false，异常版抛 SocketError。set_nonblocking 默认参数 enable = true，便于直接调用「设为非阻塞」。

4.7 Socket Option 模板接口

xxxxxxxxxx
template <typename T>
T getsockopt(int level, int optname, std::error_code& ec) const noexcept {
    ec.clear();
    T v{};
    socklen_t len = static_cast<socklen_t>(sizeof(T));
    getsockopt_impl(level, optname, &v, &len, ec);
    if (ec) return T{};
    if (len != sizeof(T)) {                    // 长度不符 → 类型选错了
        ec = std::make_error_code(std::errc::invalid_argument);
        return T{};
    }
    return v;
}


template <typename T>
void setsockopt(int level, int optname, const T& value, std::error_code& ec) noexcept;

  • T 必须为 POD（int、struct linger、struct timeval、unsigned char、struct in_addr、struct ip_mreq 等）；

  • getsockopt<T> 通过 len 出参校验：若内核返回的长度不等于 sizeof(T)，视为 invalid_argument，防止结构体版本不匹配导致的脏读；

  • setsockopt 直接传 &value 与 sizeof(T)。

底层 getsockopt_impl / setsockopt_impl 提供异常版与错误码版，做空指针防御：buf == nullptr 或 len == nullptr 返回 invalid_argument，然后才调用系统接口。

4.10 关闭与半关闭

xxxxxxxxxx

fileno() 供 Selector 注册；family() / type() 供上层判断行为（如 accept 继承 type_）。

5. Selector 模块设计

5.1 Event 位掩码

xxxxxxxxxx
enum class Event : uint32_t {
    None   = 0,
    Read   = 1 << 0,
    Write  = 1 << 1,
    Error  = 1 << 2,
    Hangup = 1 << 3,


    EdgeTrigger = 1u << 16,   // 模式位，不参与事件匹配
};

关键设计：Event::EdgeTrigger 放在 bit 16，与低 8 位的事件位隔离。原因是 has_event(set, e) 只应判断"事件"，不应把模式位当成事件。为此提供：

xxxxxxxxxx
inline Event operator|(Event, Event);
inline Event operator&(Event, Event);
inline bool has_event(Event set, Event e);
inline Event event_bits(Event e);           // 屏蔽高 24 位，只保留低 8 位事件
inline bool  has_edge_trigger(Event e);     // 检测 ET

位域划分：

  • 低 8 位（0x00~0xFF）：纯事件位，由内核报告；

  • 高位（1 << 16 起）：模式位，仅作注册标志，不会被报告。

为什么 ET 也是 Event 的 bit：让用户可以用 Event::Read | Event::EdgeTrigger 一次表达 "读 + 边缘触发"，Selector::add 一个参数搞定，无需额外 API。语义上 ET 确实是 epoll 注册参数的一部分，作为 Event 的扩展位合理。

};

NVI 模式：公有非虚接口负责异常/错误码双风格转换，私有虚接口是纯错误码版——子类实现只需写一份逻辑。add(const Socket&) 重载免去调用者手动 fileno()。

supports_edge_trigger()：供上层查询后端能力，默认 false（select/poll 不支持 ET），epoll 覆写为 true。

wait 的超时语义：

  • std::nullopt → 永久阻塞（对应 -1）；

  • 0ms → 非阻塞轮询；

  • > 0 → 超时返回空 vector（ec 为空，与出错区分）。

NVI 实现细节：异常版 add / modify / remove 内部先 std::error_code ec 调用错误码版，若 ec 非空则抛出 SelectorError(ec, "...")，what 消息前缀按操作区分（"selector add failed" 等）。

5.4 ReadyEvent

xxxxxxxxxx
struct ReadyEvent {
    int   fd;
    Event events;   // 只含 Read/Write/Error/Hangup，不含 EdgeTrigger
};

wait() 返回 vector<ReadyEvent>，调用方按顺序处理。不做 fd → 回调的分发，保持库的"零框架"定位。只包含实际就绪的 fd，未就绪的不出现，简化调用者遍历。

事件归位：后端 from_* 转换只写入事件位，不写 EdgeTrigger——ET 是注册期语义，运行时无意义。

5.5 后端选择策略

库不强制用户用哪个后端，但提供工厂契约：

xxxxxxxxxx
std::unique_ptr<Selector> make_select_selector();
std::unique_ptr<Selector> make_select_selector(std::error_code&);
std::unique_ptr<Selector> make_poll_selector();
std::unique_ptr<Selector> make_poll_selector(std::error_code&);
std::unique_ptr<Selector> make_epoll_selector();
std::unique_ptr<Selector> make_epoll_selector(std::error_code&);

5.6 select 后端

数据结构：std::map<int, Event>（有序，便于遍历时取最大 fd）。实现类禁止拷贝与移动。

注册/修改/移除：仅操作内存映射，wait 时动态构造 fd 集合。重复注册返回 AlreadyRegistered；修改/移除未注册 fd 返回 NotRegistered。

wait 实现：

  1. 遍历映射，按事件位 FD_SET 到 readfds / writefds；exceptfds 总是把所有 fd 加入（select 的异常集合对应错误/带外数据）；

  2. timeout 转换为 struct timeval（毫秒 → 秒+微秒）；nullopt 传 nullptr 表示无限等待；

  3. 执行 ::select，EINTR 重试；

  4. n < 0 → 置 ec；n == 0 → 空 vector（超时）；

  5. 遍历映射，FD_ISSET 命中读/写集合映射为 Read/Write，命中异常集合映射为 Error；ready != None 才加入结果。

5.7 poll 后端

数据结构：std::unordered_map<int, Event>（wait 时整体构造 pollfd 数组）。实现类禁止拷贝与移动。

wait 实现：

  1. 遍历映射，构造 std::vector<struct pollfd>，events 按事件位设置（Read→POLLIN，Write→POLLOUT）；

  2. timeout_ms = timeout ? static_cast<int>(count()) : -1（负值取 0）；

  3. 执行 ::poll，EINTR 重试；

  4. n < 0 → 置 ec；n == 0 → 空 vector（超时）；

  5. 遍历返回的 pollfd，revents == 0 跳过，否则 from_poll 转换；None 跳过。

事件映射（接收侧）：

POLLERR / POLLHUP / POLLNVAL 无需显式请求，poll 总会报告。

5.8 epoll 后端

数据结构：内核 epoll 实例 fd（epoll_create1(EPOLL_CLOEXEC) 创建）+ std::unordered_map<int, Event>（记录注册事件）。实现类禁止拷贝与赋值；析构时 ::close(epfd_)（若已创建）。

初始化双模式：

  • init()：失败抛 SelectorError(ec, "init failed")；

  • init(ec)：失败返回 false 并置 ec；已初始化时直接返回 true（幂等）；

  • 构造后为「未初始化」状态（epfd_ == -1）；

  • 所有操作入口经 check_init 检查，未初始化返回 EBADF（system_category）。

工厂函数：make_epoll_selector(ec) 内部构造 EpollSelector 并调用 init(ec)；失败返回 nullptr。这是 epoll 与 select/poll 工厂的唯一差异（epoll 可能初始化失败）。

add 实现：

  1. check_init，失败返回；

  2. 校验 map_.count(fd) == 0，否则 AlreadyRegistered；

  3. 构造 struct epoll_event{events = to_epoll(events), data.fd = fd}；

  4. 调用 ::epoll_ctl(EPOLL_CTL_ADD, ...)，失败置 ec（system_category）；

  5. 成功后 map_[fd] = events。

modify 实现：校验初始化、已注册（否则 NotRegistered）→ EPOLL_CTL_MOD → 成功后更新 map_。

remove 实现：校验初始化、已注册 → 调用 EPOLL_CTL_DEL→ 成功后 map_.erase(it)。

wait 实现：

  1. check_init；

  2. 计算 timeout_ms：nullopt → -1；count() <= 0 → 0；否则强转 int；

  3. 栈上 struct epoll_event evs[MAX_EVENTS]，MAX_EVENTS = 64；

  4. ::epoll_wait 调用，EINTR 重试；

  5. n < 0 → 置 ec；n == 0 → 空 vector（超时）；

  6. 遍历 evs[0..n)，{data.fd, from_epoll(events)} 构造 ReadyEvent；reserve(n) 避免多次分配。

事件映射：

to_epoll 通过 has_edge_trigger(e) 决定是否附加 EPOLLET——ET 是注册期语义，from_epoll 不会输出 ET。EPOLLERR / EPOLLHUP 内核总会报告，无需显式请求。

supports_edge_trigger() 返回 true。

6. 主机名模块

xxxxxxxxxx
namespace host {
    inline std::string local_hostname();
}

调用系统主机名查询接口（gethostname），缓冲区 256 字节，末尾强制截断为 \0 防御性处理。失败返回空串（非关键路径，不抛异常）。

设计取舍：主机名查询失败极少见且通常无补救手段，返回空串比抛异常更友好；调用者可用 empty() 判断。

7. 典型使用场景

7.1 TCP 服务端（epoll ET）

xxxxxxxxxx
unpsock::Socket listen_sock(unpsock::Family::INET, unpsock::AddrType::STREAM);
listen_sock.set_reuse_addr(true);
listen_sock.bind(unpsock::Address::any(8080));
listen_sock.listen(128);
listen_sock.set_nonblocking(true);


auto sel = unpsock::make_epoll_selector(ec);
sel->add(listen_sock, unpsock::Event::Read | unpsock::Event::EdgeTrigger);


while (running) {
    for (auto& ev : sel->wait(std::chrono::milliseconds(100))) {
        if (ev.fd == listen_sock.fileno()) {
            auto [conn, peer] = listen_sock.accept(ec);
            if (!ec) {
                conn.set_nonblocking(true);
                sel->add(conn, unpsock::Event::Read | unpsock::Event::EdgeTrigger);
            }
        }
    }
}

7.4 双风格错误处理对比

xxxxxxxxxx
// 异常版：原型验证，逻辑直白
try {
    unpsock::Socket sock(unpsock::Family::INET, unpsock::AddrType::STREAM);
    sock.connect("192.168.1.10", 8080);
    sock.sendall(data);
} catch (const unpsock::SocketException& e) {
    log("socket error: %d %s", e.code().value(), e.what());
}


// 错误码版：生产代码，避免异常开销
unpsock::Socket sock(unpsock::Family::INET, unpsock::AddrType::STREAM, ec);
if (!ec) sock.connect("192.168.1.10", 8080, ec);
if (!ec) sock.sendall(data, ec);
if (ec) log("socket error: %d %s", ec.value(), ec.message().c_str());
