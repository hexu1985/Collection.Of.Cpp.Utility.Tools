## 1. 概述

本文档介绍基于 Fast DDS 的 SOA（Service-Oriented Architecture）框架的使用方法。框架提供 RPC 风格的请求/响应通信，支持同步、异步、超时控制等调用模式。

**核心能力：**
- **服务注册与发现**：基于 DDS Topic，客户端通过服务名自动发现服务端。
- **类型安全的序列化**：支持 CDR（IDL 生成类型）、Protobuf、自定义类型。
- **四种调用模式**：`call`、`call_timed`、`async_call`、`async_call_timed`。
- **多服务、多方法**：通过 `service_name` 和 `method_name` 两级路由。

**文档结构：**
- **第 2 章**：框架核心接口说明（`EprosimaRpcClient` / `EprosimaRpcServer` / 序列化适配）。
- **第 3 章**：Daytime 示例（入门，空参数 + 字符串响应），**并详细说明客户端/服务端如何使用框架类**。
- **第 4 章**：Calculate 示例（进阶，CDR IDL 类型 + 四种调用模式），**每种模式均有文字说明**。

## 2. 框架核心接口

### 2.1 服务端接口：`EprosimaRpcServer`

#### 2.1.1 创建与生命周期

```cpp
#include "EprosimaRpcServer.hpp"

// 创建服务端实例
// service_name    : 服务名，用于构建 Topic：soa.rpc.<service_name>.request/.response
// thread_pool_size: 业务处理线程数，内部裁剪到 [1, 5]
// participant     : 可选，外部传入的 DomainParticipant；为 nullptr 时使用全局默认
static std::shared_ptr<EprosimaRpcServer> create_rpc_server(
        const std::string& service_name,
        size_t thread_pool_size,
        eprosima::fastdds::dds::DomainParticipant* participant = nullptr);

// 启动服务（创建 DDS 实体并开始监听请求）
bool start();

// 停止服务（销毁 DDS 实体）
void stop();
```

#### 2.1.2 方法注册

```cpp
// 注册一个 RPC 方法
// method_name     : 方法名，客户端调用时需一致
// process_function: 业务处理函数，签名必须为 void(const Argument&, Result&)
template <typename Argument, typename Result>
void register_method(const std::string& method_name,
        std::function<void(const Argument&, Result&)> process_function);

// 注销一个方法
void unregister_method(const std::string& method_name);
```

**业务函数约定：**

| 项 | 要求 |
| :--- | :--- |
| **签名** | `void(const Argument&, Result&)` |
| **Argument** | 请求参数类型，需支持 `DeserializeFromVector` |
| **Result** | 响应结果类型，需支持 `SerializeToVector` |
| **异常** | 业务函数抛出的异常会被框架捕获，返回 `UPPER_LAYER_APPLICATION_ERROR` |
| **线程安全** | 业务函数在 worker 线程池中并发执行，需自行保证共享状态安全 |

### 2.2 客户端接口：`EprosimaRpcClient`

#### 2.2.1 创建与生命周期

```cpp
#include "EprosimaRpcClient.hpp"

// 创建客户端实例
// client_name : 客户端名，用于生成 client_id = client_name@hostname
// service_name: 目标服务名，用于构建 Topic
// participant : 可选，外部传入的 DomainParticipant
static std::shared_ptr<EprosimaRpcClient> create_rpc_client(
        const std::string& client_name,
        const std::string& service_name,
        eprosima::fastdds::dds::DomainParticipant* participant = nullptr);

// 初始化（创建 DDS 实体）
bool init();

// 查询是否已就绪（DDS 发现完成）
bool is_ready();
```

> **注意**：在 `is_ready()` 返回 true 之前调用 `call`/`async_call`，会立即返回 `SERVICE_NOT_AVAILABLE`。建议在 `init()` 后轮询等待 `is_ready()`。

#### 2.2.2 同步调用

```cpp
// 同步调用（无超时，无限等待响应）
template <typename Argument, typename Result>
soa_on_dds::ErrorCode call(const std::string& method_name,
        const Argument& arg, Result& res);

// 同步调用（指定超时）
template <typename Argument, typename Result>
soa_on_dds::ErrorCode call_timed(const std::string& method_name,
        const Argument& arg, Result& res,
        std::chrono::milliseconds timeout);
```

**返回值**：`soa_on_dds::ErrorCode`，详见第 5 章错误码表。

#### 2.2.3 异步调用

```cpp
// 异步调用（无超时）
template <typename Argument, typename Result>
void async_call(const std::string& method_name, const Argument& arg,
        std::function<void(soa_on_dds::ErrorCode,
                           std::shared_ptr<Result>)> callback);

// 异步调用（指定超时）
template <typename Argument, typename Result>
void async_call_timed(const std::string& method_name, const Argument& arg,
        std::function<void(soa_on_dds::ErrorCode,
                           std::shared_ptr<Result>)> callback,
        std::chrono::milliseconds timeout);
```

**回调约定：**

| 情况 | error_code | result |
| :--- | :--- | :--- |
| 成功 | `SUCCESS` | 非空 `shared_ptr<Result>` |
| 超时 | `REQUEST_TIMEOUT` | `nullptr` |
| 服务不可用 | `SERVICE_NOT_AVAILABLE` | `nullptr` |
| 序列化/反序列化失败 | `CLIENT_SERIALIZE_ERROR` / `CLIENT_DESERIALIZE_ERROR` | `nullptr` |

> **回调线程**：回调在 `EprosimaRpcClient::m_main_thread` 中执行，若回调耗时较长会阻塞后续响应处理。建议回调中仅做轻量处理，耗时操作另行提交。

### 2.3 序列化适配

框架采用编译期多态，业务类型只需提供两个自由函数：

```cpp
bool SerializeToVector(const T& value, std::vector<uint8_t>& output);
bool DeserializeFromVector(T& value, const std::vector<uint8_t>& input);
```

**框架内置支持：**

| 类型 | 说明 |
| :--- | :--- |
| `soa_on_dds::VoidType` | 空类型，用于无参方法 |
| `std::string` | 字符串，字符逐一拷贝 |

**CDR IDL 类型适配**（见 `ClientServerTypesUtils.hpp`）：

```cpp
inline bool SerializeToVector(const Operation& operation, std::vector<uint8_t>& output) {
    auto size = Operation::getCdrSerializedSize(operation);
    output.resize(size);
    eprosima::fastcdr::FastBuffer fast_buffer((char*)output.data(), output.size());
    eprosima::fastcdr::Cdr cdr(fast_buffer);
    operation.serialize(cdr);
    return true;
}

inline bool DeserializeFromVector(Operation& operation, const std::vector<uint8_t>& input) {
    eprosima::fastcdr::FastBuffer fast_buffer((char*)input.data(), input.size());
    eprosima::fastcdr::Cdr cdr(fast_buffer);
    operation.deserialize(cdr);
    return true;
}
```

## 3. Daytime 示例（入门）

### 3.1 场景说明

客户端向服务端发起 `daytime` 调用，服务端返回当前本地时间字符串。

| 项 | 值 |
| :--- | :--- |
| **服务名** | `daytime.service` |
| **方法名** | `daytime` |
| **请求类型** | `soa_on_dds::VoidType`（空类型，框架内置） |
| **响应类型** | `std::string`（框架内置） |
| **调用模式** | 同步 `call`（无超时） |

### 3.2 整体调用链路

```
┌─────────────────────┐         ┌──────────────────────┐         ┌──────────────────────┐
│  DaytimeClient      │         │  EprosimaRpcClient   │         │  Fast DDS            │
│  (业务封装)          │ ──────> │  (框架代理)           │ ──────> │  soa.rpc.daytime.    │
│                     │         │                      │         │  service.request     │
└─────────────────────┘         └──────────────────────┘         └──────────────────────┘
                                                                          │
                                                                          ▼
┌─────────────────────┐         ┌──────────────────────┐         ┌──────────────────────┐
│  DaytimeServer      │         │  EprosimaRpcServer   │         │  Fast DDS            │
│  (业务封装)          │ <────── │  (框架骨架)           │ <────── │  soa.rpc.daytime.    │
│  daytime_handle     │         │  dispatch            │         │  service.request     │
└─────────────────────┘         └──────────────────────┘         └──────────────────────┘
          │                                                              ▲
          │                                                              │
          └───── 处理结果 ──> EprosimaRpcServer ──> soa.rpc.daytime.service.response
```

**关键点**：`DaytimeClient` / `DaytimeServer` 是业务封装类，内部持有一个 `EprosimaRpcClient` / `EprosimaRpcServer` 智能指针。业务类负责参数组装、结果解析、错误处理；框架类负责 DDS 通信、路由、序列化、超时。

### 3.3 DaytimeClient 如何使用 `EprosimaRpcClient`

#### 3.3.1 类结构

```cpp
class DaytimeClient {
public:
    DaytimeClient();
    virtual ~DaytimeClient();

    bool init();                       // 初始化
    std::string get_daytime();         // 业务接口
    bool isReady();                    // 服务可用性查询

private:
    std::shared_ptr<soa_on_dds::EprosimaRpcClient> mp_rpc_client;  // 框架代理
};
```

**设计要点：**

- `DaytimeClient` **不继承** `EprosimaRpcClient`，而是 **持有（has-a）** 一个 `shared_ptr<EprosimaRpcClient>`。这样做的好处：
    - 业务类与框架类职责分离，业务类可以自由定义接口签名。
    - 便于测试（可注入 mock 客户端）。
    - 生命周期由 `shared_ptr` 管理，析构时自动释放 DDS 资源。
- `mp_rpc_client` 使用 `shared_ptr` 而非 `unique_ptr`，是因为 `EprosimaRpcClient` 内部使用 `enable_shared_from_this`（在 `Timer` 回调中通过 `weak_from_this` 弱引用捕获自身）。

#### 3.3.2 构造与析构

```cpp
DaytimeClient::DaytimeClient() {
    // 构造时不做任何 DDS 操作，保持轻量
}

DaytimeClient::~DaytimeClient() {
    mp_rpc_client.reset();  // 触发 EprosimaRpcClient 析构，清理 DDS 实体与内部线程
}
```

**设计要点：**

- **构造不初始化**：DDS 初始化可能失败（端口占用、配置错误等），放在 `init()` 中返回 bool，便于调用方处理。
- **析构 `reset()`**：显式调用 `reset()` 触发 `EprosimaRpcClient` 的析构，`~EprosimaRpcClient` 会：
    1. 释放 `m_request_pub`（销毁 DataWriter → Publisher → Topic）。
    2. 释放 `m_response_sub`（销毁 DataReader → Subscriber → Topic）。
    3. `m_main_thread`（`worker_thread`）成员析构，停止线程并 join。
    4. 所有未完成的请求会被丢弃（`m_pending_requests` 中仍持有 `RequestInfo`，其 `promise` 析构会使等待的 future 抛 `broken_promise` —— 这也是为什么析构前应确保所有同步调用已返回）。

#### 3.3.3 `init()`：创建并初始化 RPC 客户端

```cpp
bool DaytimeClient::init() {
    // 步骤 1：创建 RPC 客户端实例
    //   client_name  = "daytime_client" → 生成 client_id = "daytime_client@<hostname>"
    //   service_name = "daytime.service" → 构建 Topic "soa.rpc.daytime.service.request" / ".response"
    mp_rpc_client = soa_on_dds::EprosimaRpcClient::create_rpc_client(
        "daytime_client", "daytime.service");

    // 步骤 2：初始化 DDS 实体
    //   内部会创建：
    //     - 请求 DataWriter（Topic: soa.rpc.daytime.service.request）
    //     - 响应 DataReader（Topic: soa.rpc.daytime.service.response）
    //   并注册监听器，等待 DDS 发现完成
    return mp_rpc_client->init();
}
```

**关键理解：**

- `create_rpc_client` 是静态工厂，返回 `shared_ptr`，**不做任何 DDS 操作**，仅存储 `client_name` 和 `service_name`，生成 `client_id` 和 `session_id`。
- `init()` 才真正创建 DDS 实体。若返回 false（如 participant 创建失败），则业务层可立即处理错误，不进入后续流程。
- `service_name` 决定 Topic 名。客户端和服务端使用 **相同的 service_name** 才能通信。

#### 3.3.4 `isReady()`：查询 DDS 发现状态

```cpp
bool DaytimeClient::isReady() {
    if (mp_rpc_client == nullptr) {
        return false;
    }
    return mp_rpc_client->is_ready();
}
```

**`EprosimaRpcClient::is_ready()` 内部逻辑：**

```cpp
bool EprosimaRpcClient::is_ready() {
    if (m_request_pub_matched == 1 && m_response_sub_matched == 1) {
        m_is_ready = true;
    } else {
        m_is_ready = false;
    }
    return m_is_ready;
}
```

- `m_request_pub_matched`：请求 DataWriter 匹配到的订阅者数量，由 `RequestPubListener::on_publication_matched` 更新。
- `m_response_sub_matched`：响应 DataReader 匹配到的发布者数量，由 `ResponseSubListener::on_subscription_matched` 更新。
- **只有两端都匹配成功（各至少 1 个对端）**，才认为服务可用。

**为什么需要 `isReady()` 轮询？**

DDS 是 **异步发现** 协议。`create_rpc_client` + `init()` 返回后，DDS 仍在后台进行端点匹配（通过 RTPS 的 PDP/EDP 协议）。立即调用 `call` 会因 `is_ready() == false` 返回 `SERVICE_NOT_AVAILABLE`。

```cpp
// 业务层调用方
while (!client.isReady()) {
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
}
```

**建议**：生产环境应增加超时保护，避免无限等待：

```cpp
auto deadline = std::chrono::steady_clock::now() + std::chrono::seconds(10);
while (!client.isReady()) {
    if (std::chrono::steady_clock::now() > deadline) {
        std::cerr << "服务发现超时" << std::endl;
        return -1;
    }
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
}
```

#### 3.3.5 `get_daytime()`：发起 RPC 调用

```cpp
std::string DaytimeClient::get_daytime() {
    std::string res;

    // 同步调用：call<Argument, Result>(method_name, arg, res)
    //   Argument = soa_on_dds::VoidType（空类型，框架内置序列化）
    //   Result   = std::string（框架内置序列化）
    auto error_code = mp_rpc_client->call(
        "daytime", soa_on_dds::VoidType{}, res);

    if (error_code != soa_on_dds::SUCCESS) {
        std::cout << "DaytimeClient::get_daytime error: "
                  << soa_on_dds::EprosimaRpcUtility::error_code_to_string(error_code)
                  << std::endl;
        return {};
    }

    return res;
}
```

**调用链路详解：**

```
DaytimeClient::get_daytime()
  │
  ├─ 1. mp_rpc_client->call("daytime", VoidType{}, res)
  │     │
  │     ├─ (a) is_ready() 检查 → 未就绪则返回 SERVICE_NOT_AVAILABLE
  │     ├─ (b) SerializeToVector(VoidType{}, payload) → payload 为空
  │     ├─ (c) 创建 std::promise<RPC_Response>，注册到 pending_requests_
  │     ├─ (d) 构造 RPC_Request：
  │     │       header.method_name   = "daytime"
  │     │       header.client_id     = "daytime_client@<hostname>"
  │     │       header.session_id    = <pid>
  │     │       header.request_id    = ++m_request_id_generator
  │     │       request_payload      = []（空）
  │     ├─ (e) m_main_thread.submit(do_send_request)  → DDS write
  │     └─ (f) response_future.get() 阻塞等待
  │
  ├─ 2. 服务端处理并返回 RPC_Response
  │
  ├─ 3. DDS 回调 ResponseSubListener::on_data_available
  │     └─ m_main_thread.submit(do_recv_response)
  │           ├─ take_next_sample → RPC_Response
  │           ├─ is_valid_response 校验 client_id / session_id
  │           ├─ find(request_id) → RequestInfo
  │           ├─ response_promise->set_value(rpc_response)
  │           └─ erase(request_id)
  │
  ├─ 4. response_future.get() 返回
  ├─ 5. 检查 error_code != SUCCESS → 返回错误
  ├─ 6. DeserializeFromVector(res, response_payload) → std::string
  └─ 7. 返回 res
```

**关键点：**

- **模板参数推导**：`call<Argument, Result>` 由 `arg` 和 `res` 的类型自动推导。此处 `Argument = soa_on_dds::VoidType`，`Result = std::string`。
- **空参数序列化**：`SerializeToVector(VoidType{}, payload)` 会 `payload.clear()`，返回 true。服务端 `DeserializeFromVector(VoidType&, payload)` 直接返回 true。
- **错误码**：只有 `SUCCESS` 时 `res` 才被正确填充。业务层必须检查错误码。
- **返回类型**：`std::string`，出错时返回空字符串。这是业务层的设计选择（也可返回 `std::optional<std::string>` 等更明确的类型）。

#### 3.3.6 使用示例与输出

```cpp
int main(int argc, char** argv) {
    DaytimeClient client;
    if (!client.init()) {
        std::cout << "client init failed" << std::endl;
        return -1;
    }

    // 等待 DDS 发现完成
    while (!client.isReady()) {
        std::this_thread::sleep_for(std::chrono::milliseconds(100));
    }

    // 发起 RPC 调用
    std::cout << client.get_daytime() << std::endl;
    return 0;
}
```

**输出：**

```
2026-09-16 15:30:45
```

### 3.4 DaytimeServer 如何使用 `EprosimaRpcServer`

#### 3.4.1 类结构

```cpp
class DaytimeServer {
public:
    DaytimeServer();
    virtual ~DaytimeServer();

    bool init();
    void serve();

    // 业务处理函数：签名必须为 void(const Argument&, Result&)
    void daytime_handle(const soa_on_dds::VoidType& arg, std::string& res);

private:
    std::shared_ptr<soa_on_dds::EprosimaRpcServer> mp_rpc_server;  // 框架骨架
};
```

**设计要点：**

- 与客户端对称，`DaytimeServer` **持有** 一个 `shared_ptr<EprosimaRpcServer>`。
- 业务方法 `daytime_handle` 的签名由框架约定：`void(const Argument&, Result&)`。
    - `Argument`：请求类型，由框架反序列化后传入。
    - `Result&`：响应类型，业务函数负责填充。
- 业务类可以有多个处理函数，注册到不同的 `method_name`。

#### 3.4.2 构造与析构

```cpp
DaytimeServer::DaytimeServer() {
    // 构造时不做任何 DDS 操作
}

DaytimeServer::~DaytimeServer() {
    mp_rpc_server.reset();  // 触发 EprosimaRpcServer 析构
}
```

**析构流程（`~EprosimaRpcServer`）：**

1. 调用 `stop()`，向 `m_main_thread` 提交 `do_stop`，销毁 `m_request_sub` / `m_response_pub`。
2. `m_workers`（`thread_pool`）成员析构，停止 worker 线程并 join。
3. `m_main_thread`（`worker_thread`）成员析构，停止主线程并 join。

> **注意**：如果在业务函数执行过程中析构服务端，`m_workers` 析构会等待正在执行的任务完成。若业务函数长时间阻塞（如 `operation_slow` 睡 10 秒），析构会被延迟。生产环境应确保优雅退出。

#### 3.4.3 `init()`：创建服务端、注册方法、启动

```cpp
bool DaytimeServer::init() {
    // 步骤 1：创建 RPC Server
    //   service_name     = "daytime.service"
    //   thread_pool_size = 3（框架内部裁剪到 [1, 5]）
    mp_rpc_server = EprosimaRpcServer::create_rpc_server("daytime.service", 3);

    // 步骤 2：注册 RPC 方法
    //   method_name      = "daytime"
    //   模板参数          = <VoidType, std::string>（请求/响应类型）
    //   process_function = std::bind(&DaytimeServer::daytime_handle, this, _1, _2)
    mp_rpc_server->register_method<VoidType, std::string>(
        "daytime",
        std::bind(&DaytimeServer::daytime_handle, this, _1, _2));

    // 步骤 3：启动服务（创建 DDS 实体，开始监听请求）
    return mp_rpc_server->start();
}
```

**关键理解：**

**（1）`create_rpc_server` 是静态工厂**

```cpp
static std::shared_ptr<EprosimaRpcServer> create_rpc_server(
        const std::string& service_name,
        size_t thread_pool_size,
        eprosima::fastdds::dds::DomainParticipant* participant = nullptr);
```

- 返回 `shared_ptr`，构造时 **不做 DDS 操作**。
- `thread_pool_size` 决定 `m_workers` 的大小（内部裁剪到 `[1, 5]`）。
- `participant == nullptr` 时使用 `EprosimaRpcUtility::get_default_rpc_participant()`（Domain ID = 40 的全局 participant）。

**（2）`register_method` 的类型擦除机制**

```cpp
template <typename Argument, typename Result>
void EprosimaRpcServer::register_method(
        const std::string& method_name,
        std::function<void(const Argument&, Result&)> process_function) {
    auto method_handler = std::make_shared<MethodHandler<Argument, Result>>(process_function);
    register_method_helper(method_name, method_handler);
}
```

- 内部创建一个 `MethodHandler<Argument, Result>`，其 `process` 方法完成：
    1. `DeserializeFromVector(arg, request_payload)`
    2. 调用 `process_function(arg, res)`
    3. `SerializeToVector(res, response_payload)`
- `MethodHandler` 继承自 `IMethodHandler`（抽象基类），实现 **类型擦除**，使得 `m_method_handlers` 可以用统一的 `std::function<ErrorCode(const vector<uint8_t>&, vector<uint8_t>&)>` 存储不同签名的方法。
- `register_method` 是线程安全的：内部通过 `m_main_thread.submit(do_register_method)` 提交到主线程执行，保证 `m_method_handlers` 的串行访问。

**（3）`std::bind` 绑定成员函数**

```cpp
std::bind(&DaytimeServer::daytime_handle, this, _1, _2)
```

等价于：

```cpp
[this](const VoidType& arg, std::string& res) {
    this->daytime_handle(arg, res);
}
```

`_1`、`_2` 是占位符，对应 `process_function` 的两个参数。也可直接使用 lambda：

```cpp
mp_rpc_server->register_method<VoidType, std::string>(
    "daytime",
    [this](const VoidType& arg, std::string& res) {
        this->daytime_handle(arg, res);
    });
```

**（4）`start()` 启动服务**

```cpp
bool EprosimaRpcServer::start() {
    if (m_participant == nullptr) return false;
    if (!init_request_sub()) return false;   // 创建 DataReader（soa.rpc.daytime.service.request）
    if (!init_response_pub()) return false;  // 创建 DataWriter（soa.rpc.daytime.service.response）
    return true;
}
```

- `init_request_sub()`：创建请求订阅端，绑定 `RequestSubListener`。
- `init_response_pub()`：创建响应发布端，绑定 `ResponsePubListener`。
- 返回 true 表示 DDS 实体已创建成功，**但不代表 DDS 发现已完成**。服务端无需显式等待发现完成，DDS 会自动处理。

#### 3.4.4 `daytime_handle`：业务处理函数

```cpp
void DaytimeServer::daytime_handle(const VoidType& arg, std::string& res) {
    (void)arg;  // 空参数，显式忽略

    // 获取当前本地时间
    auto now = std::chrono::system_clock::now();
    std::time_t t = std::chrono::system_clock::to_time_t(now);

    // 使用可重入版本 localtime_r，避免多线程竞争
    std::tm tm_buf{};
    if (localtime_r(&t, &tm_buf) == nullptr) {
        return;  // res 保持为空字符串
    }

    char buf[64];
    std::strftime(buf, sizeof(buf), "%Y-%m-%d %H:%M:%S", &tm_buf);
    res = buf;  // 填充响应
}
```

**关键点：**

- **函数签名**：`void(const VoidType&, std::string&)`，与 `register_method<VoidType, std::string>` 的模板参数一致。
- **线程安全**：`daytime_handle` 可能在多个 worker 线程中并发执行。因此必须使用 `localtime_r`（可重入）而非 `localtime`（使用静态缓冲区，非线程安全）。
- **异常处理**：业务函数抛出的异常会被 `MethodHandler::process` 捕获，返回 `UPPER_LAYER_APPLICATION_ERROR`。示例中未抛出异常，因为 `localtime_r` 失败只返回空字符串。
- **响应填充**：通过 `res = buf` 填充响应。框架会在 `process` 返回后调用 `SerializeToVector(res, response_payload)`。

#### 3.4.5 `serve()`：保持服务运行

```cpp
void DaytimeServer::serve() {
    cout << "Enter a number to stop the server: ";
    int aux;
    std::cin >> aux;  // 阻塞等待用户输入
}
```

**作用**：`main` 函数中调用 `serve()`，通过 `std::cin` 阻塞主线程，防止 `main` 返回导致 `DaytimeServer` 析构。用户输入任意整数后返回，`main` 结束，触发 `~DaytimeServer()`。

**生产环境替代方案**：

- 使用信号处理（`SIGINT` / `SIGTERM`）+ `std::condition_variable`。
- 使用 `std::atomic<bool>` 标志位 + 轮询。
- 使用专门的退出机制（如 DDS 的 `stop` topic）。

#### 3.4.6 服务端请求处理链路

```
1. DDS 收到请求
   └─> RequestSubListener::on_data_available(reader)
         └─> m_up->on_data_available()
               └─> m_main_thread.submit(do_recv_request)

2. do_recv_request（在 m_main_thread 中执行）
   ├─ take_next_sample → RPC_Request
   ├─ 提取 method_name = "daytime"
   ├─ get_method_handler("daytime") → MethodHandler<VoidType, std::string>
   ├─ m_workers.submit(process_request, handler, rpc_request)
   └─ 重新分配 rpc_request（避免多个 worker 共享）

3. process_request（在 worker 线程中执行）
   ├─ DeserializeFromVector(VoidType&, request_payload) → true
   ├─ 调用 daytime_handle(arg, res) → 填充 res
   ├─ SerializeToVector(res, response_payload)
   └─ m_main_thread.submit(do_send_response, response)

4. do_send_response（在 m_main_thread 中执行）
   ├─ set_send_timestamp_ms(response)
   └─ m_response_pub->write(response)
```

**线程切换示意：**

```
DDS 线程 ──> m_main_thread（串行接收） ──> m_workers（并发处理） ──> m_main_thread（串行发送） ──> DDS 线程
```

**为什么 `do_send_response` 要回到 `m_main_thread`？**

DDS `DataWriter::write` 不是线程安全的，多个 worker 线程并发写同一个 DataWriter 会导致未定义行为。通过 `m_main_thread` 串行化所有写操作，保证线程安全。

### 3.6 关键要点总结

| 要点 | 客户端 | 服务端 |
| :--- | :--- | :--- |
| **持有关系** | `shared_ptr<EprosimaRpcClient>` | `shared_ptr<EprosimaRpcServer>` |
| **构造** | 不做 DDS 操作 | 不做 DDS 操作 |
| **`init()`** | 创建 DDS 实体 | 创建 DDS 实体 + 注册方法 + start |
| **就绪判断** | 轮询 `is_ready()` | 无需轮询（DDS 自动发现） |
| **业务函数签名** | 无（调用 `call`） | `void(const Argument&, Result&)` |
| **空参数** | `VoidType{}` | `const VoidType&` |
| **`std::string` 响应** | `std::string res` | `std::string& res` |
| **线程安全** | 框架内部串行化 | 业务函数需自行保证（用 `localtime_r`） |

| **阻塞保持** | 无需（调用完即退出） | `serve()` 阻塞主线程 |

### 3.7 常见陷阱与最佳实践

#### 陷阱 1：未等待 `is_ready()` 就调用

```cpp
// 错误：可能返回 SERVICE_NOT_AVAILABLE
client.init();
client.get_daytime();  // 可能失败

// 正确：等待发现完成
client.init();
while (!client.isReady()) {
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
}
client.get_daytime();
```

#### 陷阱 2：服务端业务函数使用非线程安全 API

```cpp
// 错误：localtime 使用静态缓冲区，多 worker 线程并发会数据竞争
std::tm* tm = std::localtime(&t);

// 正确：使用可重入版本
std::tm tm_buf{};
localtime_r(&t, &tm_buf);
```

#### 陷阱 3：析构时仍有未完成的同步调用

```cpp
// 错误：析构时 promise 被销毁，future.get() 会抛 broken_promise
{
    DaytimeClient client;
    client.init();
    auto fut = std::async(std::launch::async, [&]() {
        return client.get_daytime();
    });
    // client 析构，但 get_daytime 仍在等待响应
}

// 正确：确保所有调用返回后再析构
{
    DaytimeClient client;
    client.init();
    auto result = client.get_daytime();  // 同步返回
    // 此时才析构
}
```

#### 陷阱 4：服务端 `register_method` 在 `start()` 之后

```cpp
// 错误：start() 之后注册方法可能丢失请求
mp_rpc_server->start();
mp_rpc_server->register_method<VoidType, std::string>("daytime", ...);

// 正确：先注册，再 start
mp_rpc_server->register_method<VoidType, std::string>("daytime", ...);
mp_rpc_server->start();
```

**原因**：虽然 `register_method` 内部是线程安全的，但在 `start()` 之后注册，若客户端请求恰好在注册完成前到达，服务端会返回 `METHOD_NOT_REGISTER`。

#### 最佳实践清单

| 项 | 建议 |
| :--- | :--- |
| **`init()` 返回检查** | 始终检查 `init()` / `start()` 的返回值 |
| **`is_ready()` 超时** | 生产环境应加超时保护，避免无限等待 |
| **错误码检查** | 同步调用后必须检查 `ErrorCode` |
| **业务函数线程安全** | 使用可重入 API，或对共享状态加锁 |
| **业务函数耗时** | 避免长时间阻塞，必要时增加线程池大小 |
| **优雅退出** | 服务端使用信号/条件变量替代 `std::cin` |
| **析构顺序** | 确保所有在途调用完成后再析构客户端/服务端 |
| **日志** | 使用 `EprosimaRpcUtility::error_code_to_string` 转换错误码便于排错 |

## 4. Calculate 示例（进阶）

### 4.1 场景说明

Daytime 示例展示了框架最基本的用法（空参数、同步调用）。Calculate 示例则进一步演示：

- **CDR IDL 自定义类型**作为请求/响应。
- **四种调用模式**：`call`、`call_timed`、`async_call`、`async_call_timed`。
- **超时控制**：通过 `operation_slow`（服务端睡眠 10 秒）对比超时与成功。
- **业务封装类的分离**：为每种调用模式提供独立的 `EprosimaClient` / `EprosimaClientTimed` / `EprosimaAsyncClient` / `EprosimaAsyncClientTimed` 封装类。

| 项 | 值 |
| :--- | :--- |
| **服务名** | `compute.service` |
| **方法名** | `operation`（正常）、`operation_slow`（延时 10 秒） |
| **请求类型** | `clientserver::Operation`（IDL 生成） |
| **响应类型** | `clientserver::Result`（IDL 生成） |
| **调用模式** | 四种（分别演示） |

### 4.2 整体调用链路

```
┌─────────────────────────────┐       ┌──────────────────────┐       ┌───────────────────────────────┐
│  EprosimaClient             │       │  EprosimaRpcClient   │       │  Fast DDS                     │
│  (同步)                      │       │  (框架代理)           │       │  soa.rpc.compute.service.     │
│  EprosimaClientTimed        │ ────> │                      │ ────> │  request                       │
│  (同步超时)                  │       │                      │       │                               │
│  EprosimaAsyncClient        │       │                      │       │                               │
│  (异步)                      │       │                      │       │                               │
│  EprosimaAsyncClientTimed   │       │                      │       │                               │
│  (异步超时)                  │       │                      │       │                               │
└─────────────────────────────┘       └──────────────────────┘       └───────────────────────────────┘
                                                                                │
                                                                                ▼
┌─────────────────────────────┐       ┌──────────────────────┐       ┌───────────────────────────────┐
│  EprosimaServer             │       │  EprosimaRpcServer   │       │  Fast DDS                     │
│  (统一注册两个方法)           │ <──── │  (框架骨架)           │ <──── │  soa.rpc.compute.service.     │
│  operation_handle           │       │  dispatch            │       │  request                       │
│  operation_handle_sleep_10s │       │                      │       │                               │
└─────────────────────────────┘       └──────────────────────┘       └───────────────────────────────┘
                                              │                              ▲
                                              │                              │
                                              └── 处理结果 ──> soa.rpc.compute.service.response
```

**关键点**：

- **一个服务端**（`EprosimaServer`）注册两个方法（`operation` 和 `operation_slow`），**所有客户端共享同一个服务端**。
- **四个客户端封装类**分别演示四种调用模式，接口签名略有不同，但内部都通过同一个 `EprosimaRpcClient` 完成通信。
- `operation_slow` 存在的意义：服务端主动睡眠 10 秒，让客户端能够可靠地触发超时（2 秒超时）或成功（12 秒超时）。

### 4.3 请求/响应类型定义（CDR IDL）

#### 4.3.1 IDL 定义

**`ClientServerTypes.idl`**

```idl
module clientserver {

enum OPERATIONTYPE {
    ADDITION,
    SUBTRACTION,
    MULTIPLICATION,
    DIVISION
};

struct Operation {
    OPERATIONTYPE m_operationType;
    long m_num1;
    long m_num2;
};

struct Result {
    long m_result;
};

};  // clientserver
```

**说明：**

- `OPERATIONTYPE` 枚举定义四种运算。
- `Operation` 是请求类型，包含运算符和两个操作数。
- `Result` 是响应类型，包含一个 `long` 结果。
- 使用 `fastddsgen` 工具编译该 IDL，生成 C++ 类（`ClientServerTypes.h` / `.cpp`），其中的 `Operation` 和 `Result` 类会提供 `serialize` / `deserialize` / `getCdrSerializedSize` 等 CDR 序列化接口。

#### 4.3.2 序列化适配

**`ClientServerTypesUtils.hpp`**（将 CDR 序列化接入框架）

```cpp
#pragma once
#include "ClientServerTypes.h"
#include <fastcdr/FastBuffer.h>
#include <fastcdr/Cdr.h>
#include <vector>

namespace clientserver {

inline bool SerializeToVector(const Operation& operation, std::vector<uint8_t>& output) {
    auto size = Operation::getCdrSerializedSize(operation);
    output.resize(size);
    eprosima::fastcdr::FastBuffer fast_buffer((char*)output.data(), output.size());
    eprosima::fastcdr::Cdr cdr(fast_buffer);
    operation.serialize(cdr);
    return true;
}

inline bool DeserializeFromVector(Operation& operation, const std::vector<uint8_t>& input) {
    eprosima::fastcdr::FastBuffer fast_buffer((char*)input.data(), input.size());
    eprosima::fastcdr::Cdr cdr(fast_buffer);
    operation.deserialize(cdr);
    return true;
}

inline bool SerializeToVector(const Result& result, std::vector<uint8_t>& output) {
    auto size = Result::getCdrSerializedSize(result);
    output.resize(size);
    eprosima::fastcdr::FastBuffer fast_buffer((char*)output.data(), output.size());
    eprosima::fastcdr::Cdr cdr(fast_buffer);
    result.serialize(cdr);
    return true;
}

inline bool DeserializeFromVector(Result& result, const std::vector<uint8_t>& input) {
    eprosima::fastcdr::FastBuffer fast_buffer((char*)input.data(), input.size());
    eprosima::fastcdr::Cdr cdr(fast_buffer);
    result.deserialize(cdr);
    return true;
}

}   // namespace clientserver
```

**说明：**

- 这四个自由函数构成框架的 **编译期契约**。只要类型（及其命名空间）提供了 `SerializeToVector` / `DeserializeFromVector`，就能作为 RPC 的 `Argument` 或 `Result`。
- `getCdrSerializedSize` 计算序列化后的字节数，`output.resize(size)` 预分配缓冲区。
- `FastBuffer` 直接包装 `output.data()`，`Cdr` 将对象写入该缓冲区，**零额外拷贝**。
- 反序列化同理，从 `input` 的字节直接恢复对象。

### 4.4 服务端实现（同时支持四种调用模式）

#### 4.4.1 设计思路

**一个服务端，两个方法：**

- `operation`：正常处理，立即返回结果。
- `operation_slow`：先睡眠 10 秒，再返回结果。**专门用于测试超时行为**。

**为什么需要 `operation_slow`？**

`call_timed` / `async_call_timed` 的超时行为必须在"服务端响应慢"的场景下才能观察到。若只提供 `operation`（正常快速返回），客户端永远在超时前收到响应，无法验证超时逻辑。因此示例提供 `operation_slow` 让客户端主动触发超时。

#### 4.4.2 服务端类定义

**`EprosimaServer.h`**

```cpp
#pragma once
#include "soa_on_dds_types.h"
#include "ClientServerTypes.h"
#include "ClientServerTypesUtils.hpp"
#include "EprosimaRpcServer.hpp"
#include <memory>

class EprosimaServer {
public:
    EprosimaServer();
    virtual ~EprosimaServer();

    bool init();
    void serve();
    void serve(uint32_t samples);

    // 正常处理方法
    void operation_handle(const clientserver::Operation& operation,
                          clientserver::Result& result);

    // 延时 10 秒处理方法（用于测试超时）
    void operation_handle_sleep_10s(const clientserver::Operation& operation,
                                    clientserver::Result& result);

private:
    std::shared_ptr<soa_on_dds::EprosimaRpcServer> mp_rpc_server;

    soa_on_dds::ErrorCode calculate(
            clientserver::OPERATIONTYPE type,
            int32_t num1, int32_t num2, int32_t* result);

public:
    uint32_t m_n_served;
};
```

**说明：**

- 与 `DaytimeServer` 结构相同，持有 `shared_ptr<EprosimaRpcServer>`。
- 两个业务函数签名一致：`void(const Operation&, Result&)`。
- 内部 `calculate` 是辅助函数，用于实际运算，与 RPC 框架无关。

#### 4.4.3 服务端实现

**`EprosimaServer.cpp`**

```cpp
#include "EprosimaServer.h"
#include <stdexcept>
#include <functional>
#include <thread>

using namespace clientserver;
using namespace std;
using namespace std::placeholders;

EprosimaServer::EprosimaServer() : m_n_served(0) {}

EprosimaServer::~EprosimaServer() {
    mp_rpc_server.reset();
}

bool EprosimaServer::init() {
    // 1. 创建 RPC Server（服务名 "compute.service"，3 个 worker 线程）
    mp_rpc_server = soa_on_dds::EprosimaRpcServer::create_rpc_server("compute.service", 3);

    // 2. 注册方法 "operation"（正常）
    mp_rpc_server->register_method<Operation, Result>(
        "operation",
        std::bind(&EprosimaServer::operation_handle, this, _1, _2));

    // 3. 注册方法 "operation_slow"（延时 10 秒）
    mp_rpc_server->register_method<Operation, Result>(
        "operation_slow",
        std::bind(&EprosimaServer::operation_handle_sleep_10s, this, _1, _2));

    return mp_rpc_server->start();
}

void EprosimaServer::operation_handle(const Operation& operation, Result& result) {
    int32_t m_result = 0;
    if (calculate(operation.m_operationType(), operation.m_num1(), operation.m_num2(), &m_result)
            != soa_on_dds::SUCCESS) {
        throw std::runtime_error("calculate error");
    }
    result.m_result(m_result);
}

void EprosimaServer::operation_handle_sleep_10s(const Operation& operation, Result& result) {
    std::this_thread::sleep_for(std::chrono::seconds(10));  // 模拟慢方法
    int32_t m_result = 0;
    if (calculate(operation.m_operationType(), operation.m_num1(), operation.m_num2(), &m_result)
            != soa_on_dds::SUCCESS) {
        throw std::runtime_error("calculate error");
    }
    result.m_result(m_result);
}

soa_on_dds::ErrorCode EprosimaServer::calculate(
        OPERATIONTYPE type, int32_t num1, int32_t num2, int32_t* result) {
    switch (type) {
        case ADDITION:       *result = num1 + num2; break;
        case SUBTRACTION:    *result = num1 - num2; break;
        case MULTIPLICATION: *result = num1 * num2; break;
        case DIVISION:
            if (num2 == 0) return soa_on_dds::UPPER_LAYER_APPLICATION_ERROR;
            *result = num1 / num2;
            break;
    }
    return soa_on_dds::SUCCESS;
}

void EprosimaServer::serve() {
    cout << "Enter a number to stop the server: ";
    int aux;
    std::cin >> aux;
}
```

**关键点：**

- **两个方法注册**：`operation` 和 `operation_slow` 使用相同的模板参数 `<Operation, Result>`，但不同的 `method_name`。
- **异常处理**：`operation_handle` 在 `calculate` 失败时抛出 `std::runtime_error`，框架会捕获并返回 `UPPER_LAYER_APPLICATION_ERROR`。这是演示业务异常的用法。
- **线程池**：`operation_slow` 会占用一个 worker 线程 10 秒。若并发调用多个 `operation_slow`，需注意线程池大小（3）。超出线程数的请求会排队等待。
- **`calculate` 除零**：除法除零时返回 `UPPER_LAYER_APPLICATION_ERROR`，触发业务异常路径。

### 4.5 同步调用（`call`，无超时）

#### 4.5.1 设计思路

**最基础的调用方式**：客户端调用 `call` 后阻塞，直到服务端返回响应。

**适用场景**：

- 服务端处理快速（毫秒级）。
- 客户端不介意阻塞等待。
- 调用链简单，无需复杂的并发控制。

**本例特点**：

- 调用 `operation` 方法（正常返回）。
- 无超时保护。若服务端挂起或网络中断，客户端会一直阻塞。

#### 4.5.2 客户端封装类

**`EprosimaClient.h`**

```cpp
#pragma once
#include "soa_on_dds_types.h"
#include "ClientServerTypes.h"
#include "ClientServerTypesUtils.hpp"
#include "EprosimaRpcClient.hpp"
#include <memory>

class EprosimaClient {
public:
    EprosimaClient();
    virtual ~EprosimaClient();

    bool init();
    bool isReady();

    soa_on_dds::ErrorCode calculate(
            clientserver::OPERATIONTYPE type,
            int32_t num1, int32_t num2, int32_t* result);

private:
    std::shared_ptr<soa_on_dds::EprosimaRpcClient> mp_rpc_client;
};
```

**说明：**

- 接口签名 `calculate(type, num1, num2, result)` 将 IDL 类型完全隐藏，业务调用方无需感知 `Operation` / `Result`。
- `int32_t* result` 是输出参数，配合 `ErrorCode` 返回值使用，符合 C++ 常见错误处理惯例。

#### 4.5.3 客户端实现

**`EprosimaClient.cpp`**

```cpp
#include "EprosimaClient.h"

using namespace clientserver;

EprosimaClient::EprosimaClient() {}
EprosimaClient::~EprosimaClient() { mp_rpc_client.reset(); }

bool EprosimaClient::init() {
    mp_rpc_client = soa_on_dds::EprosimaRpcClient::create_rpc_client(
        "client", "compute.service");
    return mp_rpc_client->init();
}

soa_on_dds::ErrorCode EprosimaClient::calculate(
        OPERATIONTYPE type, int32_t num1, int32_t num2, int32_t* result) {
    if (mp_rpc_client == nullptr) {
        return soa_on_dds::CLIENT_NOT_INITIALIZE;
    }

    // 1. 构造 IDL 请求
    Operation operation;
    operation.m_operationType(type);
    operation.m_num1(num1);
    operation.m_num2(num2);

    // 2. 同步调用（无超时）
    Result idl_result;
    auto error_code = mp_rpc_client->call("operation", operation, idl_result);
    if (error_code != soa_on_dds::SUCCESS) {
        return error_code;
    }

    *result = idl_result.m_result();
    return soa_on_dds::SUCCESS;
}

bool EprosimaClient::isReady() {
    if (mp_rpc_client == nullptr) return false;
    return mp_rpc_client->is_ready();
}
```

**关键理解：**

- **请求构造**：`Operation` 的 setter（`m_operationType`、`m_num1`、`m_num2`）是 `fastddsgen` 为 IDL 成员生成的访问器。
- **模板参数推导**：`call("operation", operation, idl_result)` 中，`Argument = Operation`，`Result = Result`，由 C++ 模板自动推导。
- **错误返回**：只要 `error_code != SUCCESS`，`idl_result` 内容未定义（不应读取），直接返回错误码。
- **结果读取**：`idl_result.m_result()` 是 `Result` 的 getter。

### 4.6 同步调用（`call_timed`，指定超时）

#### 4.6.1 设计思路

**在同步调用基础上增加超时保护**：客户端调用 `call_timed` 后阻塞最多 `timeout`，若超时则返回 `REQUEST_TIMEOUT`。

**适用场景**：

- 关键路径，需快速失败（fail-fast）。
- 服务端可能变慢或不可靠，需避免无限阻塞。
- 客户端希望在超时后执行回退逻辑（如重试、降级）。

**本例特点**：

- 调用 `operation_slow`（服务端睡眠 10 秒）。
- **两次调用对比**：
    - 第 1 次：`timeout = 2000ms` → 必然超时，返回 `REQUEST_TIMEOUT`。
    - 第 2 次：`timeout = 12000ms` → 服务端 10 秒后返回，成功。

#### 4.6.2 客户端封装类

**`EprosimaClientTimed.h`**

**说明：**

- 与 `EprosimaClient` 的唯一区别：`calculate` 多一个 `timeout` 参数。

#### 4.6.3 客户端实现

**`EprosimaClientTimed.cpp`**

```cpp

bool EprosimaClientTimed::init() {
    mp_rpc_client = soa_on_dds::EprosimaRpcClient::create_rpc_client(
        "client", "compute.service");
    return mp_rpc_client->init();
}

soa_on_dds::ErrorCode EprosimaClientTimed::calculate(
        OPERATIONTYPE type, int32_t num1, int32_t num2,
        int32_t* result, std::chrono::milliseconds timeout) {
    if (mp_rpc_client == nullptr) {
        return soa_on_dds::CLIENT_NOT_INITIALIZE;
    }

    Operation operation;
    operation.m_operationType(type);
    operation.m_num1(num1);
    operation.m_num2(num2);

    Result idl_result;

    // 同步调用（指定超时），调用 operation_slow 方法
    auto error_code = mp_rpc_client->call_timed(
        "operation_slow", operation, idl_result, timeout);
    if (error_code != soa_on_dds::SUCCESS) {
        std::cout << "call_timed failed: "
                  << soa_on_dds::EprosimaRpcUtility::error_code_to_string(error_code)
                  << std::endl;
        return error_code;

    return mp_rpc_client->is_ready();
}
```

**关键理解：**

- **方法名 `operation_slow`**：必须调用慢方法，否则无法触发超时。
- **`call_timed` 内部机制**：
    1. 创建 `std::promise` 并注册到 `m_pending_requests`。
    2. 发送请求。
    3. 创建一次性 `Timer`，`timeout` 后触发 `on_request_timeout(request_id)`。
    4. `future.get()` 阻塞等待。
    5. 若 Timer 先触发：`promise.set_value(timeout_response)`，`future.get()` 返回 `REQUEST_TIMEOUT`。
    6. 若响应先到达：`promise.set_value(response)`，`future.get()` 返回 `SUCCESS`。
- **错误信息**：使用 `error_code_to_string` 转换，便于日志。

### 4.7 异步调用（`async_call`，无超时）

#### 4.7.1 设计思路

**非阻塞调用**：客户端调用 `async_call` 后立即返回，响应到达时通过回调通知。

**适用场景**：

- 客户端需要在等待响应期间执行其他工作。
- 需要并发发起多个请求，提升吞吐。
- 事件驱动架构，回调中处理业务。

**本例特点**：

- 调用 `operation` 方法。
- 回调中打印结果并对比本地值。
- 主线程用 `client.wait()`（`std::cin`）阻塞，等待回调完成。

#### 4.7.2 客户端封装类

**`EprosimaAsyncClient.h`**

```cpp
#pragma once
#include "soa_on_dds_types.h"
#include "ClientServerTypes.h"
#include "ClientServerTypesUtils.hpp"
#include "EprosimaRpcClient.hpp"
#include <memory>
#include <functional>

class EprosimaAsyncClient {
public:
    EprosimaAsyncClient();
    virtual ~EprosimaAsyncClient();

    bool init();
    bool isReady();

    void calculate(clientserver::OPERATIONTYPE type,
            int32_t num1, int32_t num2,
            std::function<void(int)> result_callback);

    void wait();

private:
    std::shared_ptr<soa_on_dds::EprosimaRpcClient> mp_rpc_client;
};
```

**说明：**

- `calculate` 返回 `void`，结果通过 `std::function<void(int)>` 回调传递。
- 业务回调的参数是简化后的 `int`，隐藏了 `ErrorCode` 和 `shared_ptr<Result>`。
- `wait()` 用于阻塞主线程，等待回调完成。

#### 4.7.3 客户端实现

**`EprosimaAsyncClient.cpp`**

```cpp
#include "EprosimaAsyncClient.h"

using namespace clientserver;

bool EprosimaAsyncClient::init() {
    mp_rpc_client = soa_on_dds::EprosimaRpcClient::create_rpc_client(
        "client", "compute.service");
    return mp_rpc_client->init();
}

void EprosimaAsyncClient::calculate(
        OPERATIONTYPE type, int32_t num1, int32_t num2,
        std::function<void(int)> result_callback) {
    if (mp_rpc_client == nullptr) return;

    Operation operation;
    operation.m_operationType(type);
    operation.m_num1(num1);
    operation.m_num2(num2);

    // 异步调用（无超时）
    mp_rpc_client->async_call<Operation, Result>(
        "operation", operation,
        [this, result_callback](soa_on_dds::ErrorCode error,
                                std::shared_ptr<Result> result) {
            if (error != soa_on_dds::SUCCESS) {
                std::cout << "error: " << static_cast<uint32_t>(error) << std::endl;
                return;
            }
            result_callback(result->m_result());
        });
}

bool EprosimaAsyncClient::isReady() {
    if (mp_rpc_client == nullptr) return false;
    return mp_rpc_client->is_ready();
}

void EprosimaAsyncClient::wait() {
    std::cout << "Enter a number to stop the server: ";
    int aux;
    std::cin >> aux;
}
```

**关键理解：**

- **双层回调**：`async_call` 的 lambda 是框架回调，负责错误检查和结果提取；`result_callback` 是业务回调，由业务层提供。
- **错误处理**：框架回调中若 `error != SUCCESS`，打印错误并直接返回，**不调用业务回调**。这样业务回调只需处理成功场景。
- **`result->m_result()`**：从 `shared_ptr<Result>` 提取 IDL 结果。
- **异步回调线程**：回调在 `EprosimaRpcClient::m_main_thread` 中执行，**不应做耗时操作**。

```cpp
    // 阻塞等待回调完成
    client.wait();

    return 0;
}
```

**说明：**

- **立即返回**：`client.calculate(...)` 调用后立即返回，主线程继续执行 `client.wait()`。
- **Lambda 捕获**：捕获 `num1`、`num2`、`op_str`、`local_res` 用于回调中打印与对比。
- **等待机制**：`client.wait()` 通过 `std::cin` 阻塞，等待用户输入。实际生产环境可使用 `std::promise` / `std::condition_variable` 精确等待回调完成。

### 4.8 异步调用（`async_call_timed`，指定超时）

#### 4.8.1 设计思路

**异步 + 超时**：客户端发起异步调用后立即返回，若在 `timeout` 内未收到响应，回调会以 `REQUEST_TIMEOUT` 触发。

**适用场景**：

- 高吞吐场景，需并发发起大量请求。
- 每个请求都需超时保护，避免长期占用资源。
- 需要在超时后执行清理或降级逻辑。

**本例特点**：

- 调用 `operation_slow`（服务端睡眠 10 秒）。
- **两次调用**：
    - 第 1 次：`timeout = 2000ms` → 必然超时，回调收到 `REQUEST_TIMEOUT`。
    - 第 2 次：`timeout = 12000ms` → 服务端 10 秒后返回，回调收到成功结果。
- **两次调用几乎同时发起**，互不阻塞，展示异步并发的优势。

#### 4.8.2 客户端封装类

**`EprosimaAsyncClientTimed.h`**

```cpp
#pragma once
#include "soa_on_dds_types.h"
#include "ClientServerTypes.h"
#include "ClientServerTypesUtils.hpp"
#include "EprosimaRpcClient.hpp"
#include <memory>
#include <functional>

class EprosimaAsyncClientTimed {
public:
    EprosimaAsyncClientTimed();
    virtual ~EprosimaAsyncClientTimed();

    bool init();
    bool isReady();

    void calculate(clientserver::OPERATIONTYPE type,
            int32_t num1, int32_t num2,
            std::function<void(int)> result_callback,
            std::chrono::milliseconds timeout);

    void wait();

private:
    std::shared_ptr<soa_on_dds::EprosimaRpcClient> mp_rpc_client;
};
```

**说明：**

- 与 `EprosimaAsyncClient` 的唯一区别：`calculate` 多一个 `timeout` 参数。

#### 4.8.3 客户端实现

**`EprosimaAsyncClientTimed.cpp`**

```cpp
#include "EprosimaAsyncClientTimed.h"

using namespace clientserver;

EprosimaAsyncClientTimed::EprosimaAsyncClientTimed() {}
EprosimaAsyncClientTimed::~EprosimaAsyncClientTimed() { mp_rpc_client.reset(); }

bool EprosimaAsyncClientTimed::init() {
    mp_rpc_client = soa_on_dds::EprosimaRpcClient::create_rpc_client(
        "client", "compute.service");
    return mp_rpc_client->init();
}

void EprosimaAsyncClientTimed::calculate(
        OPERATIONTYPE type, int32_t num1, int32_t num2,
        std::function<void(int)> result_callback,
        std::chrono::milliseconds timeout) {
    if (mp_rpc_client == nullptr) return;

    Operation operation;
    operation.m_operationType(type);
    operation.m_num1(num1);
    operation.m_num2(num2);

    // 异步调用（指定超时），调用 operation_slow 方法
    mp_rpc_client->async_call_timed<Operation, Result>(
        "operation_slow", operation,
        [this, result_callback](soa_on_dds::ErrorCode error,
                                std::shared_ptr<Result> result) {
            if (error != soa_on_dds::SUCCESS) {
                std::cout << "error: " << static_cast<uint32_t>(error) << std::endl;
                return;
            }
            result_callback(result->m_result());
        },
        timeout);
}

bool EprosimaAsyncClientTimed::isReady() {
    if (mp_rpc_client == nullptr) return false;
    return mp_rpc_client->is_ready();
}

void EprosimaAsyncClientTimed::wait() {
    std::cout << "Enter a number to stop the server: ";
    int aux;
    std::cin >> aux;
}
```

**关键理解：**

- **方法名 `operation_slow`**：必须调用慢方法才能触发超时。
- **超时机制**：
    1. `async_call_timed` 创建 `ResponseProcessor<Result>` 并注册到 `m_pending_requests`。
    2. 同时创建一次性 `Timer`（`timeout` 后触发）。
    3. 若 Timer 先触发：`on_request_timeout(request_id)` → 构造 `REQUEST_TIMEOUT` 响应 → 调用 `ResponseProcessor::process` → 回调收到错误。
    4. 若响应先到达：`do_recv_response` → 调用 `ResponseProcessor::process` → 回调收到结果。
- **回调隔离**：两次调用（2 秒超时、12 秒超时）各自独立注册 `RequestInfo`，互不影响。

#### 4.8.4 客户端主程序

**`calculate_client_test_async_timed.cpp`**

```cpp
#include <iostream>
#include <chrono>
#include <thread>
#include <string>
#include "EprosimaAsyncClientTimed.h"

using namespace clientserver;
using std::cout;
using std::endl;

OPERATIONTYPE to_operation_type(const std::string& op_str) {
    if (op_str.empty()) return ADDITION;
    switch (op_str[0]) {
        case '+': return ADDITION;
        case '-': return SUBTRACTION;
        case '*': return MULTIPLICATION;
        case '/': return DIVISION;
        default:  return ADDITION;
    }
}

int main(int argc, char** argv) {
    if (argc != 4) {
        cout << "Usage: " << argv[0] << " num1 op num2" << endl;
        return 1;
    }

    int32_t num1 = atoi(argv[1]);
    std::string op_str = argv[2];
    int32_t num2 = atoi(argv[3]);

    OPERATIONTYPE op = to_operation_type(op_str);
    int32_t local_res = 0;
    switch (op) {
        case ADDITION:       local_res = num1 + num2; break;
        case SUBTRACTION:    local_res = num1 - num2; break;
        case MULTIPLICATION: local_res = num1 * num2; break;
        case DIVISION:       local_res = num1 / num2; break;
    }

    EprosimaAsyncClientTimed client;
    if (!client.init()) {
        cout << "client init failed" << endl;
        return -1;
    }
    while (!client.isReady()) {
        std::this_thread::sleep_for(std::chrono::milliseconds(100));
    }

    // 第 1 次：2 秒超时（服务端延时 10 秒，必然超时）
    client.calculate(op, num1, num2,
        [num1, num2, op_str, local_res](int res) {
            cout << "1. calculate remote: " << num1 << op_str << num2 << "=" << res << endl;
        },
        std::chrono::milliseconds(2000));

    // 第 2 次：12 秒超时（服务端延时 10 秒，应成功）
    client.calculate(op, num1, num2,
        [num1, num2, op_str, local_res](int res) {
            cout << "2. calculate remote: " << num1 << op_str << num2 << "=" << res << endl;
            if (local_res == res) {
                cout << "remote result is correct!" << endl;
            } else {
                cout << "remote result is incorrect!" << endl;
            }
        },
        std::chrono::milliseconds(12000));

    // 阻塞等待两个回调完成
    client.wait();

    return 0;
}
```

**说明：**

- **两次调用几乎同时发起**：
    - 第 1 次请求立即发送。
    - 第 2 次请求立即发送。
    - 两个请求在服务端**并发处理**（服务端有 3 个 worker 线程）。
- **回调独立触发**：
    - 第 1 次：2 秒后 Timer 触发，回调收到 `REQUEST_TIMEOUT`（错误码 8）。
    - 第 2 次：约 10 秒后服务端返回，回调收到正确结果。
- **`client.wait()`**：`std::cin` 阻塞，等待两个回调都完成后再退出。若客户端提前退出，第 2 次回调可能丢失。

### 4.9 四种调用模式对比

| 调用模式 | 接口 | 是否阻塞 | 超时 | 适用场景 | 本例调用方法 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **同步** | `call` | 阻塞 | 无 | 简单场景，服务端响应快 | `operation` |
| **同步超时** | `call_timed` | 阻塞 | 用户指定 | 关键路径，需快速失败 | `operation_slow` |
| **异步** | `async_call` | 非阻塞 | 无 | 高吞吐，回调驱动 | `operation` |
| **异步超时** | `async_call_timed` | 非阻塞 | 用户指定 | 高吞吐 + 超时保护 | `operation_slow` |

**选择建议：**

- **优先使用 `call`**：若服务端可靠且响应快，`call` 是最简单的选择。
- **需要超时保护用 `call_timed`**：关键路径、外部依赖、可能变慢的服务端。
- **需要并发用 `async_call`**：高吞吐场景，或客户端需在等待期间做其他工作。
- **两者都要用 `async_call_timed`**：既需要并发，又需要超时保护。

### 4.11 常见陷阱与最佳实践

#### 陷阱 1：IDL 定义与序列化适配不一致

```cpp
// 错误：IDL 中 m_num1 是 long，但适配函数未正确实现
inline bool SerializeToVector(const Operation& operation, std::vector<uint8_t>& output) {
    // 若遗漏某个字段，会导致对端反序列化失败
}

// 正确：使用 fastddsgen 生成类的 CDR 序列化方法
operation.serialize(cdr);
```

#### 陷阱 2：`operation_slow` 占用 worker 线程

```cpp
// 服务端有 3 个 worker 线程
// 若同时有 3 个 operation_slow 请求，第 4 个请求会排队等待
// 建议：分离"慢方法"到独立的服务或增加线程池大小
```

#### 陷阱 3：异步回调中做耗时操作

```cpp
// 错误：回调在 m_main_thread 中执行，阻塞会导致后续响应处理延迟
client.calculate(op, num1, num2, [](int res) {
    std::this_thread::sleep_for(std::chrono::seconds(10));  // 阻塞！
}, timeout);

// 正确：回调中仅做轻量处理，耗时操作提交到其他线程
client.calculate(op, num1, num2, [](int res) {
    std::async(std::launch::async, [res]() {
        // 耗时操作
    });
}, timeout);
```

#### 陷阱 4：异步调用后立即析构客户端

```cpp
// 错误：异步调用未返回，客户端析构会丢弃回调
{
    EprosimaAsyncClient client;
    client.init();
    client.calculate(op, num1, num2, [](int res) { /* ... */ }, timeout);
    // client 析构，回调永远不触发
}

// 正确：等待所有回调完成后再析构
{
    EprosimaAsyncClient client;
    client.init();
    std::promise<void> done;
    client.calculate(op, num1, num2,
        [&done](int res) { done.set_value(); }, timeout);
    done.get_future().wait();
}
```

#### 最佳实践清单

| 项 | 建议 |
| :--- | :--- |
| **IDL 序列化** | 使用 `fastddsgen` 生成的 `serialize` / `deserialize` 方法 |
| **业务异常** | 在业务函数中抛出异常会被框架捕获为 `UPPER_LAYER_APPLICATION_ERROR` |
| **慢方法隔离** | 避免慢方法占用 worker 线程，可拆分到独立服务 |
| **异步回调** | 回调中不做耗时操作，必要时提交到其他线程 |
| **异步等待** | 使用 `promise` / `condition_variable` 精确等待回调完成 |
| **超时选择** | 关键路径用较短超时，非关键路径用较长或无超时 |
| **结果验证** | 对比本地计算与远程结果，及时发现逻辑错误 |
| **线程池大小** | 根据并发量和业务函数耗时合理设置（上限 5） |

| 错误码 | 值 | 含义 | 常见原因 |
| :--- | :--- | :--- | :--- |
| `SUCCESS` | 0 | 成功 | — |
| `UPPER_LAYER_APPLICATION_ERROR` | 1 | 业务异常 | 业务函数抛出异常（如除零） |

## 6. 最佳实践

### 6.1 服务端

- **`init()` 中注册所有方法**：方法注册应在 `start()` 之前完成，避免请求到达时方法尚未注册。
- **业务函数保持短小**：业务函数在 worker 线程池中执行，长时间阻塞会占用线程。耗时操作应异步化或增加线程池大小（上限 5）。
- **异常处理**：业务函数抛出的异常会被框架捕获，返回 `UPPER_LAYER_APPLICATION_ERROR`。建议在业务函数内部处理可预期的错误。
- **线程安全**：多个 worker 线程并发执行业务函数，共享状态需加锁或使用原子操作。
- **`serve()` 阻塞**：示例中的 `serve()` 通过 `std::cin` 阻塞，实际生产环境可使用信号、条件变量等机制优雅退出。

### 6.2 客户端

- **等待 `is_ready()`**：首次调用前必须轮询等待 `is_ready()` 返回 true，否则会收到 `SERVICE_NOT_AVAILABLE`。
- **超时选择**：
    - 关键路径：使用较短的 `call_timed`（如 1-2 秒），快速失败。
    - 非关键路径：使用 `call` 或较长的 `call_timed`。
- **异步回调**：回调在 `EprosimaRpcClient::m_main_thread` 中执行，避免在回调中做耗时操作。
- **生命周期**：`EprosimaRpcClient` / `EprosimaRpcServer` 使用 `shared_ptr` 管理，确保在所有在途请求完成后再释放。

### 6.3 序列化

- **CDR IDL 类型**：使用 `fastddsgen` 生成类型后，参照 `ClientServerTypesUtils.hpp` 编写适配函数。
- **Protobuf 类型**：使用 `ByteSizeLong` + `SerializeToArray` / `ParseFromArray`。
- **自定义类型**：可使用 JSON、MessagePack 等序列化库，只需提供两个自由函数。
